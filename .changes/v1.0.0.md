# v1.0.0 (2026-08-22)

## 🎯 核心重构：生活事件监控完全对齐参考项目

### 四象限决策矩阵（新增）

参考 p115strmhelper 实现，根据「旧路径是否在媒体映射」和「新路径是否在媒体映射」两个维度，将 move/rename 事件路由到 4 个象限：

| 象限 | oldIsMedia | newIsMedia | 处理策略 |
|------|-----------|-----------|---------|
| OTHER_TO_MEDIA | ❌ | ✅ | 清理旧 STRM + 在新位置创建 |
| MEDIA_TO_MEDIA | ✅ | ✅ | move/rename（local_move 原子搬移 或 recreate 删旧+生新） |
| MEDIA_TO_OTHER | ✅ | ❌ | 删除旧 STRM + 空目录清理 |
| OTHER_TO_OTHER | ❌ | ❌ | 按文件名兜底搜索（可选） |

### 事件类型路由（对齐参考项目）

| 事件类型 | type 值 | 路由到 |
|---------|---------|--------|
| 创建（含回收站还原） | 1, 2, 14, 18, 23 | handleCreateEvent |
| 移动 | 5, 6 | handleMoveRenameQuadrant（四象限） |
| 重命名 | 20, 24 | handleMoveRenameQuadrant（四象限） |
| 删除 | 22 | handleRemoveEvent |

### fallback 全部移除（行为对齐参考项目）

- rename 失败直接返回错误，不再降级 recreate
- move 失败直接返回错误，不再降级 recreate
- 与参考项目 `shutil_move` 抛异常行为一致

## 🐛 关键 Bug 修复

### STRM 路径映射丢失子目录（严重）

**根因**：4 处代码错误使用 `filepath.Dir(mapping.localPath)`，导致 STRM 生成在错误位置。

| 修复位置 | 修复前 | 修复后 |
|---------|--------|--------|
| handleCreateEvent | `filepath.Dir(mapping.localPath)` | `mapping.localPath` |
| handleMoveEvent | `filepath.Dir(mapping.localPath)` | `mapping.localPath` |
| handleRenameEvent | `filepath.Dir(mapping.localPath)` | `mapping.localPath` |
| handleRemoveEvent | `filepath.Dir(mapping.localPath)` | `mapping.localPath` |

**场景**：映射 `电影` → `dist\Strm`，云路径 `电影/小王子` → `mapping.localPath = dist\Strm\小王子`
- 修复前：`filepath.Dir` = `dist\Strm`，STRM 生成在 `dist\Strm\movie.strm` ❌
- 修复后：直接用 `mapping.localPath` = `dist\Strm\小王子\movie.strm` ✅

### DB 提前覆盖旧路径（严重）

**根因**：`handleMoveRenameQuadrant` 在 handler 内部反查旧路径**之前**就把新路径写入 DB，导致反查到新路径，走"本地无旧 STRM"分支只 create 不 delete。

**修复**：删除提前写 DB 调用，handler 内部在 rename/move 成功后才同步 DB。

### recreate 模式不生成新 STRM

**根因**：配置 `moveMediaCreateNewStrm: false` 挡住了所有新 STRM 创建。

**修复**：recreate 模式**强制创建**新 STRM，不再被配置开关挡住（删旧+生新是 recreate 的核心语义）。

### OTHER_TO_MEDIA 象限旧 STRM 未清理

**根因**：OTHER_TO_MEDIA 象限只创建新 STRM，未清理旧 STRM。

**修复**：新增 `cleanupOldStrmForOtherToMedia` 函数，创建新 STRM 前按 file_id 反查旧路径并删除。

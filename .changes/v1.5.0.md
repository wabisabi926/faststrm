# v1.5.0 - 2026-10-20

清理可信、配置一致的一版。原 v1.4.3 未单独发布，其全部改动已并入本版本。

## 亮点速览

* 本版本同时包含未发布的 v1.4.3 全部改动：115 目录递归清单扫描、按 pickcode 对账清理、按账号×用途限流、SSE 实时日志、模板变量扩展、账号改名/删除级联等
* 清理闭环补齐：本工具生成的 STRM 进入托管表，手写/第三方 STRM 默认不删；删除先进回收站，可一键恢复
* 扫描结果绑定服务端快照（`scanId`）：执行只能删除本次扫描确认过的路径，伪造路径/摘要直接拒绝
* 删除前再次复核云端：云端文件已恢复、目录查询失败或缺少云端路径时一律保留
* 首次登录强制修改默认口令；登录失败按 IP 限速；管理接口 CORS 收紧为同源
* 设置改为锁内原子读改写，多个页面同时保存不再互相覆盖；补配置契约测试
* ISO/原盘播放修复：`Content-Disposition` 不再输出非法路径分隔符，HEAD/代理流补齐 `Content-Type`

## ✨ 新增

* STRM 托管所有权：新增 SQLite `managed_strms` 表，记录本地路径、账号、云端路径、pickcode、file_id、SHA256、size、mtime、来源与状态；全量任务、生活事件、清理补建写入后自动登记
* 历史 STRM 一次性纳管：启动时异步扫描已有文件，仅纳管「标准 `/api/strm` 或 `/api/fs/get` URL + 合法 pickcode + 账号存在 + 云端索引命中」的文件；手写/第三方 STRM 保持未托管
* 清理扫描分类：托管孤儿 / 未托管 / 漏生成；未托管默认不进入删除候选，清理页展示数量
* 扫描快照与 `scanId`：扫描结果服务端保存 30 分钟（最多 8 份，按用户绑定）；执行必须携带 `scanId`，删除/补建范围从快照重建
* 回收站：删除动作先移动到 `<映射根>/.faststrm-trash/<时间戳>/...`，保留 7 天；新增回收站列表与恢复 API/UI，恢复后自动重新登记托管
* 删前云端复核：按托管记录的 `cloud_path` 列出父目录，确认同名文件/pickcode 是否仍存在；手动清理、`delete_all`、待确认批次、全量自动清理全部接入
* 登录安全：默认 `admin/admin` 检测与强制改密门禁；登录失败 5 次 / 15 分钟窗口 / 15 分钟封禁，按 TCP 对端地址计数
* 播放响应头：`Content-Disposition` 清理 `/`、控制字符并按 RFC 5987 编码；HEAD/代理流按扩展名补 `Content-Type`（ISO/TS/MKV/MP4 等）

## ⚡ 优化

* 清理默认值：`removeRelatedFiles` / `removeEmptyDirs` 默认关闭；新增 `CleanupDefaultsV3` 一次性迁移，旧版本自动开启过的动作会关闭一次，之后尊重手动设置
* 三重保护补齐：手动清理与 `delete_all` 也按「比例 + 绝对 + 目录数」判定；`delete_all` 同样支持二次确认队列
* 关联文件删除统一：清理页、待确认批次、Emby 删除同步统一到 `strmutil` 白名单实现，支持 `movie.zh.srt`、`.webp`、`.vtt` 等
* 清理路径防呆：execute/scan/preview 只允许已配置映射根或任务目标目录，拒绝 `../`、绝对路径、软链、非 `.strm`
* 设置原子化：`SettingsStore.Update` 锁内完成读-改-写；settings/Emby/生活监控/通知/账号级联/媒体挂载/Telegram 菜单全部迁移
* 配置契约：GET→POST→GET 全字段回环、脱敏字段保留、部分提交保留未提供字段；补上 `strmFilenameTemplate` / `forceProxyFormats` / `strmMaxConcurrent` 的写入
* 未托管/复核保留提示：清理结果展示因归属变化、云端恢复、复核失败而保留的数量；有保留项时前端自动复扫
* 健康检查版本跟随构建版本，不再固定返回旧版本号

## 🐛 修复

* ISO 文件名含 `/` 时 `Content-Disposition` 输出非法 `filename*`，部分播放器识别失败/无法起播
* HEAD/代理流缺少容器 `Content-Type`，原盘/TS 识别不稳定
* 清理页把「所有云端不存在的本地 STRM」都当作待删，手写/第三方 STRM 存在误删风险
* 清理执行信任前端传入的路径与扫描摘要，可能删除映射外文件或绕过扫描结果
* 删除后云端文件恢复、目录查询失败时仍继续删除的问题
* 多个设置页面并发保存时互相覆盖（read-modify-save 竞态）
* 默认管理员口令长期可用且无登录限速
* 管理接口 CORS 反射任意来源
* 连带删除关联文件/空目录在升级时被自动打开，可能删除用户同名资产

## 🔥 删除 / 行为变更

* `/api/strmCleanup/execute` 现在必须携带 `scanId`；没有有效快照的请求会被拒绝，需要重新扫描
* 默认 `admin/admin` 登录后必须先改密，未改密前所有受保护接口返回 `PASSWORD_CHANGE_REQUIRED`
* 首次启动 v1.5.0 会把自动开启过的「连带删除关联文件/空目录」关闭一次；需要时在设置页重新勾选
* 管理接口 CORS 收紧为同源；`/api/strm`、`/api/fs/get` 播放端点仍允许跨源
* 仍不提供完整路径式 URL、URL 签名、增量同步、`export_dir`；ISO 直连 302 的最终 CDN URL 已带扩展名，完整路径不再是必需项

## ⚙️ 配置提示

* 升级后首次启动会执行 `managed_strms` 迁移并异步纳管历史文件；纳管完成前自动清理只会跳过未登记文件
* 扫描快照有效期 30 分钟；清理页放置过久后执行会提示「扫描结果不存在或已过期」
* 删前云端复核需要托管记录包含 `cloud_path`。早期生活事件 move/rename 记录可能缺失，这类文件会判为「未确认」并保留；重新生成/重扫后可补全
* 旧 `settings.json` 中的 `removeRelatedFiles` / `removeEmptyDirs` 会在 V3 迁移时关闭一次；这是一个有意的安全默认值变更

## 📦 并入 v1.4.3（未单独发布）

v1.4.3 原计划单独发布；因与 v1.5.0 同期完成且未打 tag，全部内容并入本版本。以下为 v1.4.3 的完整记录。

### 亮点速览

* 全量扫描改用 115 目录递归清单：调用次数从「每个目录 1 次」降到「每 1000 个文件 1 次」，大库热启动快一个数量级
* 清理只按 STRM 内容里的 pickcode 对账，不再按路径删除，你手动放的海报 / 字幕 / 手写 STRM 不会被误删
* 删除影片时可以选择连带清理同名 nfo / 海报 / 字幕，也可以顺手收掉空目录
* 扫描、播放取直链、生活事件分别限流，后台扫描不再挤占播放配额
* 生活事件更可靠：移出监控目录可自动清理旧 STRM；文件名含 `/`、emoji 等特殊字符也能正确落盘与回读

### ✨ 新增

* 全量扫描走 115 目录递归清单（`cur=0`）：一次请求返回 1000 个文件并自带父目录 id，本地用目录缓存还原路径；缓存缺失时用列目录响应的祖先链补齐并回填。清单不完整、路径还原失败、空清单等异常自动回退旧扫描，生成结果不受影响
* 清理新增两个可选动作：连带删除同名 `.nfo/.jpg/.png/.srt/.ass` 等元数据与字幕（扩展名白名单，不含任何视频格式）、删完后向上回收空目录（到任务目标目录为止）
* 关联文件下载幂等：本地已存在且大小一致时跳过，不再每轮重下全部字幕 / 海报
* 代理流直链过期自动刷新：上游返回 401/403/404/408/429/5xx 时自动失效缓存并重取一次直链，外网播放中途不再因 CDN 签名过期中断
* 单文件生活事件的 pickcode 延迟可用时自动重试（2s / 5s），覆盖「整理刚完成、pickcode 还没生成」导致的漏生成
* 移出监控目录时可自动删除本地旧 STRM（默认开启，可在设置页关闭）：文件移到非媒体目录后，旧位置的 STRM、关联文件与空目录一并清理；关闭时保留旧 STRM 并记录日志
* STRM URL 模板变量扩展：新增 `{file_path}`、`{file_path_raw}`、`{file_id}`、`{file_name}`、`{file_stem}`、`{file_suffix}`、`{base_url}`，与 p115strmhelper 的模板写法兼容；原有 `{prefix}`、`{account}`、`{pickcode}`、`{filename}`、`{ext}`、`{stem}` 保持不变
* 前端任务页接入 SSE 实时事件：任务进度与日志边跑边刷新，无需手动刷新页面；日志详情页 SSE 优先（服务端重放最近 500 帧 + 增量推送），4 秒未连通自动降级为一次性拉取
* 账号改名 / 删除级联：改名同步任务、设置、数据库与监控引用；删除时展示被引用详情，支持强制删除
* Telegram 交互增强：命令别名、返回按钮、批次过期提示、任务进度回执；全量同步改为选择任务、孤儿清理改为独立对账；`/status` 显示最近 3 条生活事件；任务 / 映射选择超过 8 个按钮时折叠并提示到 Web UI 操作；按钮映射改为 LRU（容量 1024、TTL 7 天，使用中的按钮不会被淘汰）
* 任务 ID 可读化：新建任务 ID 从时间戳改为「账户-目录名」，特殊字符清洗、UTF-8 安全截断、重名追加序号；旧任务 ID 保持不变
* 生活事件类型汉化补全：轮询 / 移出 / 重建 / 新建文件夹 / 卡住超时等类型均有中文标签与颜色，未知类型兜底显示原文
* 生活事件页新增「清理轮询」：一键删除历史轮询噪音（只删 `poll` 类型，业务事件不受影响）；轮询日志默认隐藏，统计区提示已隐藏条数

### ⚡ 优化

* 限流按「账号 + 用途」分桶：扫描 60、播放取直链 120、生活事件 60 QPM，互不抢占
* STRM 写入去重：内容未变时跳过写盘，也不触发 Emby 刷库，避免媒体库假重扫
* 目录级失败容忍：单个目录列目录失败不再让整个任务作废，扫描结束统一重试一轮；仍失败的目录记入任务日志，其下存量 STRM 本次跳过清理
* 清理三重保护：单次删除超过 10%、超过 1000 个、或涉及超过 20 个目录时进入保护态，任务日志明确说明原因
* 清理默认改为按 pickcode 对账（原来默认是「按路径删除多余文件」）
* 改名 / 移动残留识别：pickcode 仍在云端但本地路径与云端不一致的 STRM，按残留清理
* 文件名非法字符清理规则补全：冒号转全角；`/`、`\` 转 `_`（避免文件名里的 `/` 被当成目录分隔符，把单个文件拆成多级目录）；其余特殊字符转下划线；`.iso.strm` 双扩展名保持不变
* 115 字符引用解码：115 返回的 `\x02<码点>` 编码（emoji 等特殊字符）在任务扫描、生活事件、下载直链、CDN 文件名等处统一还原为真实字符，STRM 文件名不再出现 `_128074]` 之类的乱码
* URL 参数编码统一：空格编码为 `%20` 而非 `+`（避免回读文件名带加号），全量生成、生活事件、模板渲染、清理补建四处规则完全一致
* 清理对账键与生成侧落盘规则对齐，同一个文件不再出现两套路径
* Emby 反代缓存 TTL 按 115 直链签名剩余时间收敛，避免缓存比签名活得久
* 强制代理格式可配置，可以把 `.ts` 等非原盘格式移出列表，改走 302 直连
* 跳过 BDMV 原盘视频流时在任务日志显式提示数量与原因
* 任务启动不再调用 115 目录导出接口：省掉最多 30 秒的启动等待，也不再在 115 侧创建无用的 zip 导出任务
* 扫描日志降噪：逐文件日志从 Info 降到 Debug，大库不再刷出十万行日志
* 扩展名归一化去重：去空白、去点、转小写并去重，`.iso` 与 `iso` 不再并存
* 账号页交互：新增账户不再自动生成时间戳名（重名返回 409 并引导更新已有账户）；「更新 Cookie」按钮常显；删除被引用账户时展示引用详情
* 失效 STRM 列表新增「账号失效」徽标，并透传 115 错误码
* 任务管理页列宽调整，浅色主题下徽章对比度优化
* Telegram 发送失败降噪：同类错误 5 分钟只记一次；连续失败 5 次暂停发送 10 分钟（期间不发起请求），恢复后只提示一次；Webhook 通道不受影响
* 生活事件建 STRM 时内容未变则跳过 Emby 刷库（与全量任务的写入去重语义对齐），重复事件不再触发媒体库假重扫
* 内部收敛：STRM 内容生成、写盘去重、空目录回收由三份实现合并为单份（`strm.BuildContent` / `strmutil.WriteStrmFile` / `strmutil.RemoveEmptyParentsUpTo`），全量任务、生活事件、清理补建三条链路输出逐字节一致，避免再出现「改一处漏两处」

### 🐛 修复

* 未配置 STRM 前缀时可能生成 `http://0.0.0.0:8090` / `127.0.0.1` 这类不可播放地址：现在按「任务 > 全局 > 对外地址 > 内网 IP」逐级兜底，彻底不可用时任务直接失败并提示
* 生活事件监控的 STRM 扩展名硬编码，不跟随设置里的扩展名列表
* 含特殊字符（冒号、问号、星号等）的片名在 Windows / SMB 上无法生成 STRM
* 清理可能误删用户自己放的文件：路径级「删除多余文件」下线
* 增量对账在云端清单不完整时可能误删本地 STRM：增量模式下线，统一走带 DB 快照兜底的全量对账
* 生活事件回退查找（DB 无旧路径时按文件名匹配本地目录）未清理特殊字符，含 `/` 的名字永远匹配不到
* 清理补建的 STRM 与生成侧格式不一致：默认 URL 缺 `file_name`，`{file_path}` 系列模板变量还是本地形态（全角冒号、系统分隔符），现统一反推为云端形态
* 删除同步还原云端路径时未处理全角冒号，导致路径对不上
* 账号失效检出覆盖扫描的全部失败路径（正常 / 缓存 / 云端失败），不再只在部分路径生效
* 监控保存时校验引用的账户是否存在，缺失返回 400 并列出账户名
* 账号改名与已有账户重名时返回 409，避免静默覆盖
* 前后端字段不对应、文案与交互细节修复
* Telegram 按钮失效、动作空实现、回调鉴权等交互缺陷
* 监控状态接口 `fromId` / `fromTime` / 连续失败次数 / 退避截止等字段恒为 0：`Status()` 只拷贝了 5 个字段，前端游标与退避状态永远显示初始值
* 清理补建的前缀兜底写死 `127.0.0.1:8090`：未配置前缀时补建出来的 STRM 只有本机能播；现与生成侧同一套解析（空 / 回环 / 0.0.0.0 → 内网 IP，仍不可用则明确报错）
* 清理补建放行非法 pickcode（非 17 位）：生成的是必然返回 400 的死链，现直接判失败并列出文件
* 清理补建内容缺结尾换行，与生成侧不一致，全量重扫会判定「内容变化」重写并触发刷库
* 空目录回收在 Windows 上缺大小写不敏感判定，理论上可能越过映射根一直删到盘根；现在无边界或越界一律不删

### 🔥 删除

* 增量同步模式（`incrementalSync` / `incrementalCleanupMode`）：它并不减少扫描，只省写盘与下载；写盘去重与下载幂等已覆盖其收益，且它的清理路径不并 DB 快照
* 任务级「删除多余文件」开关与全局 `removeExtraFiles` 配置（后者执行器从未读取）
* 任务启动时的 115 目录导出调用（`ExportDirParse`）

### ⚙️ 配置提示

* 原 v1.4.3 计划中的清理默认值（`auto_clean` + 连带删除）已由 v1.5.0 的安全默认值覆盖：v1.5.0 首次启动会关闭「连带删除关联文件/空目录」，清理策略仍为 `auto_clean`；请以本页上方的 v1.5.0 配置提示为准
* 旧任务配置里的 `removeExtraFiles` 字段会被忽略，不需要手动清理
* 冷启动（目录缓存为空）第一次扫描速度与旧版持平，跑完一次后明显变快
* URL 编码开关（默认开启）：关闭后账号、文件名等参数原样写入 URL，文件名含 `#` / `&` / `?` / 空格 时会破坏 URL 解析
* 移出映射删除开关（默认开启）：关闭后文件移出监控目录时只记录日志，不删除本地旧 STRM
* 清理补建现在会拒绝非法 pickcode 与不可用前缀：日志出现「pickcode 无效」「STRM 前缀不可用」时，先补全 STRM 前缀配置再重跑补建

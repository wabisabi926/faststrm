v0.9.5 - 2026-08-20

## 跨平台本地目录浏览大修（飞牛 fNOS / Docker / Linux / Windows）

针对 v0.9.4 在飞牛 fNOS 沙箱下"只能看到 @appshare 一个目录、无法选择媒体文件夹"的 P0 问题彻底修复。

### 后端 directory.go — 核心修复

- **`defaultRoots` 重写为 4 级优先根列表**（从高到低，任一级命中即作为根列表）：
  1. `FASTSTRM_LOCAL_DIR_ROOTS` 环境变量（逗号分隔，用户/管理员显式覆盖）
  2. Linux：读取 `/proc/mounts` 真实挂载点，过滤 proc/sysfs/devpts/cgroup/overlay/tmpfs 等虚拟 FS；Windows：保持盘符枚举不变
  3. fNOS 并集：`TRIM_DATA_*` 白名单 ∪ NAS 常见卷根（`/vol1~/vol4`、`/volume1~/volume4`、`/mnt/user|ssd|cache|disk`、`/share|public|home`）
  4. 兜底：普通 Linux 硬编码常见目录 + `/`
- **`isPathAllowed` fNOS 默认宽松**：之前只要不在白名单就 403，导致 `/vol1/电影` 这类用户已授权但 manifest 未声明的路径直接被拒。现在除非显式设置 `FASTSTRM_FNOS_STRICT_PATH=1`，否则一律放行，只打 warning 日志
- **新增 `readRealMountpoints()`**：跨平台安全（非 Linux 直接返回 nil），用 FS 类型 + 路径前缀双重过滤虚拟 FS

### fNOS manifest（amd64 / arm64）— 沙箱实际访问权

- 新增 `share_dirs = /vol1,/volume1,/mnt/user,/mnt/ssd,/mnt/cache,/mnt/disk,/share,/public,/home` 字段，对齐 qmediasync 共享路径声明规范
- 用户在飞牛「应用管理 → faststrm → 共享目录」勾选共享文件夹后，沙箱里会真正 bind mount 进来，同时写入 `TRIM_DATA_SHARE_PATHS` 供后端枚举

### 前端 LocalDirectoryTreeDialog.tsx — UI 兜底通道

- 顶部新增 **手动路径输入框（等宽字体 + Enter 提交）+ 「跳转」按钮**（带 loading / 禁用态）
- 三路校验状态反馈：✅ `ok`（绿色 + 条目数）/ ❌ `err`（红色 + 后端错误原文，含沙箱授权 / 权限 / 路径是否存在提示）/ 💡 idle（用户输入时提示 Enter / 跳转）
- 选择树节点会同步回填输入框，对话框关闭自动清理状态

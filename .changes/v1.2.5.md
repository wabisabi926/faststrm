# v1.2.5 - 2026-09-02

STRM 清理对账功能全面修复与强化版本 —— 按钮不再无效、对账统一口径、
失效 STRM 内容可预览、扫描默认 1 分钟缓存，告别全 "-" 和重复云端请求。

## ✨ 新增

* **统一 ScanResponse**：「扫描路径映射」「全量对账」两个按钮后端已合并为同一 handler，
  返回完全一致的聚合字段（totalRemoteFiles / totalLocalStrms / totalStale /
  totalMissing / totalDbRecords / totalAssociatedFiles），对账详情新增 DB 记录数列
* **STRM 内容预览**：新增 POST /api/strmCleanup/preview 接口 + 失效 STRM 弹窗
  「查看完整」按钮，扫描时预读前 512B，列不再全是 "-"
* **扫描缓存默认启用**：1 分钟内重复扫描自动走缓存（useCache=true + cacheTTLMs=60000），
  CleanupToolbar 显示绿色缓存提示 Badge，避免重复云端 FsDirGetID
* **完整端到端测试**：后端 12 条 E2E + 26 条 handler 单测、前端 31 条 Vitest，
  覆盖统一响应 / 选中删除 / 补生成同步 / 关联文件拆分 / 预览 / 缓存等全部场景

## ⚡ 优化

* **防累计漂移**：delete / regenerate 等磁盘操作后，自动走「轻量本地 re-scan」（只 Walk
  本地不查 115）刷新 totalLocalStrms 绝对值，覆盖前端增量估算的精度偏差
* **统计语义纯净**：totalLocalStrms 不再混入 .nfo / .jpg / .png / .srt / .sub /
  .ass / .vtt 等关联文件数量，关联文件单独走 totalAssociatedFiles 聚合字段，
  Mapping 明细行也新增 associatedFileCount
* **组合按钮文案修正**：「清理失效 + 补生成漏项」确认弹窗按 **选中条目数量** 显示
  （之前误显示为全量），未选中时直接禁用

## 🐛 修复

* 修复「清理全部失效」按钮无效：原后端遍历前端传入 body.Entries（空数组）导致
  0 删除；现从 ScanSummary.Mappings 中直接提取失效 STRM 路径执行
* 修复「补生成全部漏项」按钮无效：原 regenerate 分支无后端实现；现复用 PickCode +
  模板生成流程，并返回 regeneratedPaths 让前端同步状态
* 修复「清理失效 + 补生成漏项」组合按钮删全量：原误走 deleteAllStaleFromScan；
  现改为 deleteSelectedStale，仅删除用户勾选的条目
* 修复补生成后 missing 列表不刷新：前端没消费 regeneratedPaths；现根据该字段
  过滤 missingStrms，并刷新本地计数
* 修复「全量对账」dbRecordCount 恒为 0：未接入 SQLite；现注入 StrmCleanupDeps.SQLiteDB
  并通过 CountFilesByPrefix 查询，修复路径归一化（斜杠 / 前缀 / 反斜杠）问题
* 修复 SQLite CountFilesByPrefix 路径归一化 bug：Windows 下反斜杠路径与 DB 内
  正斜杠不一致，统计全部命中 0

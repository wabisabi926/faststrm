# v1.1.2 - 2026-08-28

首个 CI 驱动的工程化版本：Go Test + golangci-lint + Vitest + 跨平台 Build 全覆盖；Swagger API 文档上线；Playwright E2E 最小集；老用户 settings.json 迁移补齐 iso 扩展名；清理 golangci-lint 无效配置。

## ✨ 新增

### GitHub Actions CI Workflow（P0）

* 完整 CI 流水线：Go Test + golangci-lint + 前端 Vitest + 跨平台 Build（linux amd64/arm64 + windows amd64）
* Go Test 带覆盖率统计，覆盖率产物自动上传 artifact
* golangci-lint 通过 `go install` 源码编译（避开 release binary 的 Go 版本不匹配问题）
* 前端 Vitest 运行 + Vite build 验证，确保 SPA 可正常打包
* CI 失败时自动上传 test output artifact，便于定位问题
* 触发条件：push / PR 到 go / master / main 分支

### API Reference — Swagger UI（P2）

* 新增 `/api/docs`（swagger.json）与 `/api/docs/ui`（Swagger UI CDN）两个端点
* Swagger UI 提供在线 API 浏览、参数填写、Try It 功能
* swagger.json 由 `scripts/gen_swagger.js` 自动生成，随 CI 构建嵌入二进制

### Playwright E2E 最小集（P1）

* 新增 `frontend/e2e/smoke.spec.ts` 4 条冒烟测试
* 覆盖健康检查、Swagger 端点存在性、登录页渲染、错误密码反馈

## ⚡ 优化

### Settings 迁移补齐新默认值

* `ReadSettings()` 从"仅空覆盖"升级为"定向迁移 + 回写"
* 老用户 settings.json 启动时自动追加 v1.1.2 新增的 `.iso` 扩展名到 StrmExtensions
* 其他零值字段（ForceProxyUaTokens / AccountProxyConcurrencyLimit / RedirectCheckTimeoutMs）一并补齐
* 迁移幂等：完成一次后不再触发，也不破坏用户自定义值

### golangci-lint 配置精简

* 移除无效的 `typecheck`（v1.57+ 已内置为分析机制，不是独立 linter）
* 移除对未启用 linter（errcheck / gosec / staticcheck）的死 `exclude-rules`
* 配置从 "3 个有效 linter + 一堆无效条目" 收敛到干净的 3 条 enable + 必要的 exclude-dirs

### AccountStore flush 排序

* `flushLocked()` 在写 JSON 前先按 Name 排序，保证输出顺序稳定（消除 map 迭代随机导致的测试失败）

### golangci-lint CI 方案切换

* 从 golangci-lint-action（依赖 release binary，v1.64.8 用 go1.24 构建，与 go.mod 1.25 不兼容导致 exit code 3）
* 改为 `go install github.com/golangci/golangci-lint/cmd/golangci-lint@v1.64.8`，用项目 Go 版本本地编译，完美对齐

## 🐛 修复

* 修复老用户 settings.json StrmExtensions 缺少 `.iso`：后端虽然在 `DefaultStrmExtensions` 加了，但已有 settings.json 的用户不会触发"空值覆盖"逻辑，iso 永远进不来
* 修复 golangci-lint 配置引用无效 linter 名称（typecheck）导致静默降级
* 修复 golangci-lint CI 因 Go 版本不匹配（release binary go1.24 vs 项目 go1.25）持续 exit code 3
* 修复 AccountStore 测试偶发失败：map 迭代顺序随机导致 bob 的密码字段有时匹配到 alice 的加密密码值

# v1.5.3 - 2026-10-21

## 亮点速览

* 清理结果可信：补建 STRM 先套媒体规则，配置文件名模板的用户不再全库判失效
* 设置项留空即恢复默认：不再出现「清空了保存却没反应」
* 运行记录可追溯：任务日志落库，历史「日志」按钮不再空白
* 清理页操作更直接：添加路径映射立即生效，回收站可一键清空
* 去掉几个「看着能点、实际无效」的开关与统计

## ✨ 新增

* 运行记录支持查看历史日志：任务结束时把执行日志落库（单次最多 2000 行），执行记录保留最近 200 条
* 回收站「清空」按钮：一键丢弃全部可恢复副本，需二次确认；新增 `POST /api/strmCleanup/trash/purge`
* 清理扫描新增 `skippedMissing` 统计：云端存在但按生成规则不该建 STRM 的条目数
* 失效 STRM 列表按原因分组计数（云端已删 / 账号已不存在），便于判断该不该删
* 待确认批次执行成功后自动刷新回收站与本地统计
* Telegram 授权用户支持一键添加：检测到通知会话是个人聊天时，提示把该 ID 加为授权用户
* 删除同步的路径映射支持「添加即保存」，不必再点一次「保存设置」

## ⚡ 优化

* User-Agent / STRM 扩展名 / 元数据扩展名统一为「留空 = 恢复内置默认值」，保存后回填生效值并提示恢复了几项
* 强制代理 UA 标识说明明确「留空 = 全部 302 直连」，与其它字段的「留空恢复默认」区分开
* Telegram「聊天 ID」补充 `(chat_id)` 与个人/群差异说明；欢迎消息直接回传发送者的 User ID
* 执行历史页更名为「运行记录」；页签「任务执行」→「任务运行」、「STRM 记录」→「事件处理」
* 全量任务不再重复写 STRM 历史，两个页签不再出现同一次运行的副本；旧记录标记为「全量任务（旧记录）」
* 清理页页头「刷新」同时刷新策略、待确认批次与回收站，三个刷新按钮语义不再打架
* 5 个二次确认弹窗统一为同一个组件，文案口径一致
* 清理默认值与标签收敛到单一来源；删除逻辑由 4 份合并为 1 份
* 批量操作后不再「本地改状态 + 全量复扫」双写，避免统计漂移
* 设置中心重构：导航合并账号/任务入口，限流区块并入「115 请求控制」
* 移除「覆盖模式」设置：写盘去重已按内容比较，该开关只会导致改前缀后重跑全跳过
* 移除删除同步的「同时删除网盘源文件」开关：后端从未实现该能力，勾选不会有任何效果
* 原盘强制代理默认列表收敛为 5 项（iso/bdmv/bdav/dvd/bluray），m2ts/ts/vob 作为普通流走 302

## 🐛 修复

* 配置 STRM 文件名模板后，清理对账仍按 `{stem}.strm` 比对，导致全库被判「云端已删除」
* 回收站恢复后 `cloud_path` 被空值覆盖，该文件此后永久跳过清理
* 清理扫描与补生成未套用媒体规则，会给 `.txt`/`.zip`/trailer/BDMV 视频流补建 STRM
* 关闭「删除 STRM 本身」后，清理仍提示成功并把条目从列表移除，刷新后又回来
* 待确认批次执行未校验 24 小时有效期，Web UI 可执行已过期批次
* 执行转入待确认或被阈值拦截时扫描结果已被消费，用户必须重新扫描才能重试
* 任务历史的「日志」按钮永远空白：`task_logs` 从未被写入
* 生活事件历史 taskID 恒为 `monitor`，无法定位到具体事件
* 任务运行记录的「删 N」恒为 0，实际删除数从未统计
* 设置页 `stableThreshold` 默认值与后端不一致（前端 100、后端 5）
* 强制代理格式列表在旧配置为空时被回填默认值，导致「全部直连」的选择失效
* CI 的 goimports 格式检查因文件末尾多余空行失败

## 升级说明

* **已有安装**：直接覆盖二进制即可，`settings.json` 中的 `syncDeleteSource` 与 `overwriteMode` 残留键会被忽略，下次保存后自动消失
* **配置了 STRM 文件名模板的用户**：升级后首次清理请先「扫描」确认失效数量恢复正常；之前被误判的条目不会自动删除
* 执行记录改为只保留最近 200 条（含日志）；更早的记录会在新任务创建时自动裁剪
* 回收站「清空」不可恢复，请确认无需回滚后再使用
* 全量任务不再写入「事件处理」页签，历史数据仍保留并可查看

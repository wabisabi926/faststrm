# v1.3.9 - 2026-10-07

外部播放器按钮可见、8097 播放不再中断、直链解析失败优雅回退的一版。

## 亮点速览

* 修复外部播放器起播按钮不显示：Emby Web 把令牌放在查询参数而非请求头，导致起播链接注入被静默跳过
* 修复经代理端口（8097）播放失败：PlaybackInfo 改写后未同步 Content-Length 头，浏览器报 ERR_CONTENT_LENGTH_MISMATCH
* Emby 反代媒体直链解析失败改为 302 回退原始 STRM URL（对齐 MoviePilot），不再在代理侧直接 502

## 🐛 修复

* 外部播放器起播按钮不显示：Emby Web 详情页等 GET 请求把令牌放在 `?X-Emby-Token=` 查询参数而非请求头，`extractAPIKey` 原先只读请求头导致 apiKey 为空，起播链接注入被静默跳过、详情页一个按钮都不出；现新增查询参数兜底（X-Emby-Token / api_key / X-MediaBrowser-Token），请求头优先级保持不变
* 经代理端口播放失败：`modifyPlaybackInfo` 改写 PlaybackInfo 响应体后只更新了 `resp.ContentLength`，未同步 `Content-Length` 响应头，浏览器以 `net::ERR_CONTENT_LENGTH_MISMATCH` 中断请求，表现为「当前没有兼容的流 / Failed to fetch」弹窗；现三处改写分支均同步改写 Content-Length
* 媒体直链解析失败改为 302 回退原始 STRM URL：对齐 MoviePilot 的 `_resolve_redirect`，解析不到上游直链（超时 / STRM 端点报错）时不再在代理侧直接返回 502，而是 302 回退原始 STRM URL，交由客户端再走一次 STRM 端点，避免把「115 Cookie 失效」这类上游问题伪装成代理故障
* 网盘挂载同步结果区分「已按设置跳过 reload」与「系统未检测到 nginx」：`NginxResult` 新增 `skipped` 字段，用户主动跳过不再被误显示为系统未检测到 nginx

## 🔧 优化

* Emby 反代诊断日志增强：`resolveRedirectChain` 透出上游状态码，302 回退日志区分「STRM 端点返回 4xx/5xx（疑似 115 Cookie 失效 / 直链过期）」与「上游无响应 / 超时」，播放失败定位更快
* 补齐回归测试：`extractAPIKey` 查询参数令牌与「请求头优先于查询参数」矩阵覆盖

# v1.0.7 - 2026-08-25

Telegram 通知代理支持、重试机制全面上线，生活事件监控可靠性增强，通知排版与 Emby 集成优化。

## ✨ 新增

### Telegram 代理支持
- 新增 Telegram 通知代理配置：支持 HTTP / HTTPS / SOCKS5 协议，解决国内网络无法直接访问 Telegram API 的问题
- 新增 `CreateBotFromSettings` 工厂函数，根据配置自动创建带代理的 Bot 实例
- 新增前端代理 URL 配置输入框，支持实时保存和热更新

### Telegram 重试机制
- 新增通知发送重试机制：网络波动时自动重试 2-3 次（无代理 2 次，有代理 3 次），仅对超时错误重试
- 新增指数退避重试间隔（1s / 4s / 9s），提高通知发送成功率

## 🔥 删除

### 生活事件监控
- 移除删除事件熔断保护逻辑：删除事件不再进行批量统计和熔断判断，直接处理单个删除事件，避免移动/重命名时旧文件无法删除的问题
- 移除网盘存在性校验：删除事件不再调用 FsFiles API 检查文件是否存在，简化删除流程

## ⚡ 优化

### 生活事件监控
- 移动/重命名事件目标已存在时改为 fallback 到 recreate 模式（清理旧 STRM + 重新生成），不再直接跳过

### 通知系统
- `Dispatcher.ApplySettings` 支持代理变更时自动重建 Bot 实例，无需重启服务
- `TelegramBot` 新增 `ProxyURL()` getter 方法，支持读取当前代理配置
- TG 通知内容行去掉加粗和缩进，Emby 状态行添加加粗，排版更清晰
- TG 通知问候语添加 `/start` 和 `/help` 命令

### Emby 通知
- 播放通知进度直接从 Webhook 的 `PlaybackInfo` 获取，减少额外 API 请求
- 入库通知详情获取改用带用户 ID 的 API 端点，解决偶发 404 或权限不足问题
- 播放通知模板对齐 qmediasync 风格：统一 emoji 前缀、半角冒号、简介标题格式

## 🐛 修复

- 修复 Telegram 通知在国内网络环境下完全无法发送的问题（需配置代理）
- 修复移动/重命名事件目标路径已存在时被直接跳过、STRM 不更新的问题
- 修复删除事件熔断保护导致移动/重命名时旧文件无法删除的问题
- 修复播放通知进度获取需要额外请求 Emby API 的性能问题

# v1.4.0 - 2026-10-08

8097 播放更稳、起播注入更可靠、日志更安静的一版。

## 亮点速览

* 修复 8097 播放报「当前没有兼容的流」：直链流拦截兼容 `(?:emby/)?` 前缀与容器后缀，播放器不再拿不到可 Seek 的代理流
* 修复 Emby 反代改写 JS/HTML 后起播按钮等注入静默失效：剥离条件请求头与正文校验头，避免 304 与陈旧缓存回吐未注入的旧页面
* 媒体 302 按 115 签名剩余有效期下发 `Cache-Control`，签名过期不再被客户端/中间缓存复用而失效起播
* 上游失败日志降噪：客户端主动取消不再刷屏，同一路径的重复失败按时间窗口去重

## 🐛 修复

* 8097 播放报「当前没有兼容的流 / Failed to fetch」：反代自生成的直链流拦截正则 `staticDirectStreamRE` 仅匹配 `/videos/{id}/stream`，未兼容 Emby 带 `/emby/` 前缀的路径与 `.mkv` / `.ts` 等容器后缀，导致这类请求漏过拦截被当作普通请求回源，播放器拿不到可 Seek 的代理流；现正则与 `mediaRoutePatterns` 同时兼容 `(?:emby/)?` 前缀与可选容器后缀，并保持 `Static=true` 校验
* Emby 反代改写 JS/HTML 后注入失效：被改写正文的响应此前仍携带上游的 `If-Modified-Since` / `If-None-Match` / `If-Range` 条件请求头与 `ETag` / `Last-Modified` / `Content-MD5` 正文校验头，客户端可能命中 304 或陈旧缓存，拿到未注入的旧页面，起播按钮等注入静默失效；现在改写正文后统一剥离条件请求头与校验头，并用显式关闭环境代理的独立 Transport 直连上游，避免部署机 `HTTP_PROXY/HTTPS_PROXY` 误伤内网 Emby 导致 502
* 媒体 302 直链缓存过久导致签名过期后起播失败：反代下发的最终直链是带签名的短时 URL（115 的 `t` 参数），若客户端或中间缓存把这次 302 缓存过久，签名过期后再次起播必然失败；现新增 `mediaRedirectCacheControl`，把可缓存时长收敛为「min(反代缓存 TTL, 签名剩余有效期)」并下发 `private, max-age=N`，解析不到签名则 `no-store`

## 🔧 优化

* 上游失败日志降噪：`isClientGone` 区分「客户端主动取消 / 连接关闭」与真实上游故障，前者不再记为 WARN；`warnUpstream` + `warnThrottle` 对同一 key（方法 + 路径）的重复失败按时间窗口只放行首条、其余累计并在下次放行时一并报告，避免刷屏
* 全局收敛 Referrer：所有响应统一下发 `Referrer-Policy: no-referrer`，Emby Web / 播放器拉流时不再携带反代地址，既避免泄露内网地址，也避免被 CDN 作为来源校验拒绝（对齐 MoviePilot `embyreverseproxy`）
* 补齐回归测试：直链流前缀/后缀矩阵与 seek 判定、上游告警抑制语义、JS/HTML 补丁剥离语义、媒体 302 缓存有效期与 Referrer-Policy 覆盖

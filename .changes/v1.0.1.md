v1.0.1 - 2026-08-24

## 任务管理 UX 优化 + Telegram / Emby 通知质量升级

### 修复

- 修复 Emby 播放/入库等通知完全不发送（全局 client==nil 判断阻塞了所有未初始化过的调用方，通知分发器隔离失败）
- 修复 STRM 任务启动/完成/失败时 Telegram 通知不触发（executor 未接入 TaskNotifier 接口，通知 dispatcher 调用链断裂）
- 修复 Telegram Bot 按钮点击无响应（Webhook/NotifyPollingPOST 使用未初始化的 deps.CommandHandler，改为懒加载 cmdHandler 注入）
- 修复开机自动轮询不启动（server.Run 启动时未检查 settings.Telegram.AutoPolling 标志，遗漏自动启 Polling 逻辑）
- 修复 Telegram 通知排版错位（中文/Emoji 宽度不等导致对齐错乱，全量替换缩进空格为 &nbsp; 并统一粗体包裹）
- 修复生活监控"通知重复发送"（event_handler 中同一事件在 write_db 与 move 两个分支双调用 NotifyWithPhoto，60s batcher 内重复入队）
- 修复 Emby 通知缺少图片（ImageTags 大小写未匹配导致 BuildImageURL 产出 404，且 TG 服务器无法访问内网 Emby URL，现下载为临时文件再 multipart 上传）
- 修复 Emby 播放暂停/停止通知缺"⌛ 观看时长"字段，参考 qmediasync 补齐
- 修复 Emby 通知演员头像图标，统一参考项目风格由 👤 改为 👥

### 新增

- 新增 RuntimeState.Stage / StageDetail 字段，定义 9 个阶段常量：starting / scanning / incremental / cleanup / writing_db / generating / finalizing / completed / failed
- 新增 SSE ProgressPayload.Stage / StageDetail 字段，阶段状态随进度帧推送到前端
- 新增 listAllFilesRecursive 扫描心跳：每 3 秒广播「已扫描 N 个目录, M 个文件 (命中 K 个媒体)」，大库扫描阶段 UI 不再是静止的 0%
- 新增任务面板阶段徽章：🔍 扫描目录 / 📊 增量比对 / 🧹 清理文件 / 💾 写数据库 / ⚡ 生成 STRM / 🔧 收尾处理 等彩色带图阶段标识
- 新增任务面板已用时间计时器（每秒刷新，格式「3分42秒」/「1时05分20秒」），用户能判断"任务还活着"
- 新增 scanning 阶段骨架进度条：条纹 shimmer + 青色扫光块循环动画，消除"大库首扫看起来卡死"的感知焦虑

### 优化

- Emby 通知模板对齐 qmediasync：清晰度 / 设备信息 / 播放格式 / 封面图尺寸升级到 720p
- BuildImageURLIfAvailable 改为大小写不敏感查找 ImageTags.Primary / Backdrop / Thumb，兼容不同 Emby 版本返回字段
- NotifyWithPhoto 与 dispatchRaw 图片路径统一采用「下载到临时文件 → SendPhotoFromFile」策略，绕过内网 Emby 对 TG 服务器不可达问题
- executor 所有阶段（启动 / 扫描 / 增量 / 清理 / 写DB / 生成 / 收尾 / 完成 / 失败）均设置 Stage 并广播到前端，失败路径完整同步错误信息
- Emby 入库 / 播放 / 暂停 / 停止 通知排版对齐 qmediasync 风格

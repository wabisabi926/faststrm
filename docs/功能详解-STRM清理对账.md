# 功能详解 - STRM 清理对账

## 概述

随着时间推移，本地 STRM 文件可能与 115 网盘实际状态不一致（手动删除、移动、API 异常等）。STRM 清理对账功能帮助发现并修复这些不一致。

## 三种清理方式

### 1. 孤儿扫描

**场景**：本地有 STRM，但 115 网盘对应文件已不存在。

**操作**：
1. 进入「STRM 清理」页面
2. 选择账号和目录
3. 点击「扫描孤儿」
4. 扫描完成后显示孤儿列表
5. 确认后点击「执行清理」

**清理动作**：
- STRM 文件移入 `.trash/` 回收站（7 天保留）
- 删除 filePathDb 中对应记录
- 清理空目录

### 2. 全量对账（reconcile）

**场景**：本地 STRM 与 115 网盘双向对比，找出差异。

**操作**：
1. 点击「全量对账」按钮
2. 系统会：
   - 暂停生活监控（避免竞争）
   - 递归扫描 115 网盘
   - 对比本地 STRM + filePathDb
   - 列出：缺失的 STRM（需生成）/ 多余的 STRM（需删除）/ DB 幽灵记录（需清理）
3. 确认后执行修复
4. 恢复生活监控（finally 块保证）

**DB 幽灵记录**：filePathDb 中有记录，但本地 STRM 和 115 网盘都不存在。通过 `removeGhostRecords` 清理。

### 3. 回收站管理

`.trash/` 目录保留 7 天内删除的 STRM：
- 手动删除事件触发的 STRM
- 孤儿扫描清理的 STRM
- 任务执行时删除的多余 STRM

**恢复操作**：
1. 进入 `.trash/` 目录
2. 找到对应文件（按删除时间命名子目录）
3. 手动移回原位置

> 7 天后自动物理删除，无法恢复。

## 清理流程详解

```
触发清理（手动/定时）
  ↓
suspendMonitorForFullScan(account)  暂停生活监控
  ↓
递归扫描 115 网盘目录
  ↓
收集 seenFileIds（本次扫描看到的文件 ID）
  ↓
对比本地 STRM：
  - 网盘有 + 本地无 → 需生成
  - 网盘无 + 本地有 → 孤儿，移入回收站
  - 网盘有 + 本地有 → 检查路径是否一致，不一致则更新
  ↓
removeGhostRecords(seenFileIds)  清理 DB 幽灵记录
  ↓
removeEmptyParents  清理空目录（保护映射根目录）
  ↓
clearMonitorSuspend(account)  恢复生活监控（finally）
  ↓
TG 通知清理结果
```

## 防误删机制

| 机制 | 说明 |
|------|------|
| 回收站 | 所有删除先移入 `.trash/`，7 天保留 |
| 空目录保护 | `removeEmptyParents` 通过 `rootDirs` 参数保护映射根目录 |
| 监控暂停 | 清理期间暂停生活监控，避免竞争 |
| 超时恢复 | `FULLSCAN_TIMEOUT_MS = 10分钟`，超时自动恢复监控 |
| 三层保护 | 清理函数 + 路由层 finally + 超时兜底 |

## 定时清理

可在任务配置中设置 cron 定时执行清理：

```json
{
  "type": "cleanup",
  "cron": "0 4 * * 0",
  "account": "我的115",
  "path": "/电影"
}
```

> 建议每周执行一次全量对账，频率不要太高（消耗 115 API 配额）。

## 性能参考

| 目录规模 | 扫描耗时 | API 调用次数 |
|----------|----------|-------------|
| 100 文件 | < 10 秒 | ~10 |
| 1000 文件 | 1 分钟 | ~50 |
| 10000 文件 | 10 分钟 | ~500 |

> API 调用受令牌桶限流保护，不会触发 115 频控。

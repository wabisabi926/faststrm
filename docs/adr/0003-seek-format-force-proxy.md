# ADR 0003：原盘格式在两层都强制代理

- 状态：已接受
- 日期：2026-10-21

## 背景

ISO/BDMV 等格式在 302 后由客户端直连 CDN，Range 请求可能因 UA 绑定、签名过期或 CDN 节点行为被拒；表现为加载卡住、seek 黑屏或无法播放。

## 决策

`strm.forceProxyFormats`（默认 `iso/bdmv/bdav/dvd/bluray`）同时作用于：

1. `/api/strm` 路由决策；
2. Emby 反代的媒体流处理。

命中原盘格式时走服务端 Range 代理，不降级 302。普通格式仍默认 302。

统一开关为 `strm.disableSeekFormatProxy`；关闭后两层都回到 UA 白名单/默认 302。

## 后果

- 原盘播放更可靠，代价是 NAS 带宽和连接数增加。
- 普通视频不额外占用 NAS 带宽。
- 原盘代理并发超过上限时排队，而不是用 302 冒险。
- `m2ts`/`ts` 默认不在列表内；需要时用户可手动加入。

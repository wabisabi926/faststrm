# 操作指南 - 115 直连模式（302 重定向）配置

## 概述

115 直连模式（302 重定向）是 FastStrm 提供的高效播放方案：STRM 文件指向本地 Go 服务的 `/api/fs/get` 接口，播放器请求时，Go 服务一次性获取 115 CDN 直链并通过 HTTP 302 重定向返回，播放器直接从 115 CDN 下载视频流。

**核心优势**：
- **零本机带宽消耗**：视频流不经过部署设备，直接从 115 CDN 到播放器
- **利用 CDN 专线**：115 CDN 节点多、带宽大，播放速度更快
- **节省服务器资源**：不占用服务器 CPU、内存和上行带宽

## 工作流程

```
┌─────────────┐     ┌──────────────────────┐     ┌─────────────┐
│  Emby 播放器  │────▶│  FastStrm Go 服务      │────▶│  115 CDN    │
│             │     │  (端口: 8090)         │     │  直链下载    │
│  读取 STRM  │     │                      │     │             │
│             │     │  1. 解析 STRM URL    │     │             │
│  GET http:// │     │  2. 调用 115 API     │     │             │
│  localhost:  │     │     获取直链          │     │             │
│  8090/api/  │     │  3. 返回 302 跳转    │     │             │
│  fs/get?... │     │     Location: CDN URL │     │             │
│             │     │                      │     │             │
└─────────────┘     └──────────────────────┘     └─────────────┘
       │                                                   │
       └──────── 跟随 302，直连 CDN 下载 ◀────────────────────┘
```

### STRM 文件内容

启用 302 后，生成的 STRM 文件内容为：

```
http://localhost:8090/api/fs/get?account=user1&pickcode=1a2b3c4d5e6f&file_name=电影.mp4
```

| 参数 | 说明 |
|------|------|
| `account` | 115 账号名 |
| `pickcode` | 115 文件唯一标识 |
| `file_name` | 文件名（用于 Content-Disposition） |

### 对比：代理模式 vs 直连模式

| | 代理模式 (proxy) | 直连模式 (302) |
|---|---|---|
| STRM 路由 | `/api/strm` | `/api/fs/get` |
| 数据流向 | 播放器 → Go → CDN → Go → 播放器 | 播放器 → Go(302) → CDN → 播放器 |
| 本机带宽 | 全量占用 | **零占用** |
| 本机 CPU | 高（流式转发） | 低（仅做一次 302） |
| 稳定性 | 高 | 依赖 115 CDN |
| 播放器兼容性 | 全部 | 需支持 302 + Range |
| 适用场景 | 移动播放器（Infuse 等） | Emby Server / Kodi / Jellyfin |

## 配置步骤

### 第一步：设置 STRM 前缀

1. 打开 FastStrm Web UI
2. 进入 **设置** -> **STRM 生成设置（全局默认）**
3. 在 **Strm 前缀** 填入你的服务地址：

```
http://<你的服务器IP>:<端口>
```

例如：
```
http://192.168.1.100:8090
```

> 端口号就是 FastStrm 服务的端口，默认为 `8090`，查看 `settings.json` 的 `server.port` 字段。

### 第二步：启用 302 重定向

1. 在 **STRM 生成设置** 区域，勾选 **"302 重定向（直链下载，不走本机代理）"**
2. 勾选后，**STRM 前缀** 字段的提示文字会说明自动追加 `/api/strm`（这个提示是针对代理模式的，开启 302 后实际走 `/api/fs/get`）

> 注意：启用 302 后，新生成的 STRM 文件会自动使用 `/api/fs/get` 路由。已有的 STRM 文件需要**重新生成**才能生效。

### 第三步：配置 Emby 媒体库

1. 打开 Emby 管理后台
2. 进入 **设置** -> **媒体库**
3. 确保媒体库的 **媒体源路径** 指向 FastStrm 生成的 STRM 文件目录
4. 点击 **刷新媒体库** 或 **扫描媒体库文件**

### 第四步：验证播放

1. 在 Emby 中打开任意一部电影或电视剧
2. 点击播放
3. 如果正常播放，说明配置成功

## 重新生成 STRM 文件

启用 302 后，需要重新生成 STRM 文件才能生效。

### 方式一：TG 菜单触发（推荐）

在 Telegram 机器人对话中：
1. 发送 `/start` 打开菜单
2. 点击 **🎬 任务管理**
3. 点击对应的任务或 **全量同步** 按钮

### 方式二：Web UI 触发

1. 打开 **任务管理** 页面
2. 点击对应任务的 **执行** 按钮
3. 等待任务完成

### 方式三：手动删除后重新生成

1. 删除本地 STRM 目录下的所有 `.strm` 文件
2. 触发全量同步任务重新生成

## 路由策略（高级）

即使开启了 302，FastStrm 仍内置了智能路由决策机制：

### 决策流程

```
播放器请求 /api/strm
        │
        ▼
  ┌─────────────────────┐
  │ 检查 UA 是否强制走代理 │───是──▶ 走 proxy
  └─────────┬───────────┘
            │否
            ▼
  ┌─────────────────────┐
  │ 重定向可达性检测     │───失败──▶ 降级为 proxy
  │ (HEAD 请求 CDN URL)  │
  └─────────┬───────────┘
            │成功
            ▼
  ┌─────────────────────┐
  │ 检查 proxy 并发数    │───超限──▶ 降级为 redirect
  └─────────┬───────────┘
            │未满
            ▼
       根据配置决定
  (redirect 或 proxy)
```

### 可配置项

在 **设置** -> **STRM 路由策略** 区域：

| 配置项 | 说明 | 示例 |
|--------|------|------|
| **强制代理 UA 标识** | 以下 UA 强制走 proxy（即使开启了 302） | `Infuse, VidHub, SenPlayer` |
| **单账号代理并发上限** | 超过此并发数自动降级为 redirect | `8` |
| **Redirect 检测超时** | HEAD 请求超时时间（毫秒） | `5000` |

### 为什么需要强制代理 UA？

某些播放器（如 Infuse）对 HTTP 302 + Range 的支持不完善，会导致：
- 拖动进度条失败
- 播放卡顿
- 无法 seek

如果你使用这些播放器，可以在 **强制代理 UA 标识** 中加入它们的 UA，FastStrm 会自动为这些请求走 proxy 模式。

## 常见问题

### Q: 开启 302 后播放失败怎么办？

1. **检查 STRM 内容**：用文本编辑器打开一个 `.strm` 文件，确认内容为 `http://.../api/fs/get?...`
2. **检查端口可达性**：在浏览器中直接访问 `http://localhost:8090`，确认服务正常
3. **检查 Cookie 有效性**：运行 `/status` 查看账号 Cookie 状态
4. **检查 115 直链获取**：查看 FastStrm 日志，搜索 `[FS/GET]` 开头的日志，看是否有错误

### Q: 已有的 STRM 文件需要重新生成吗？

**是的**。开启 302 不会自动修改已有 STRM 文件内容，必须重新生成。

### Q: 302 和代理模式可以混用吗？

**可以**。路由策略会根据 UA、并发数、CDN 可达性自动决策。大部分请求走 302，特殊情况自动降级为代理。

### Q: 302 模式下 Emby 识别不到文件？

可能是 Emby 的 UA 不在 302 兼容列表中。检查 Emby 的请求 UA，如果是自定义的，可能需要调整 `ForceProxyUaTokens` 配置。

### Q: 带宽占用很大？

如果开启 302 后带宽仍然很高，检查是否有强制走 proxy 的请求。可以通过 `ForceProxyUaTokens` 清空不需要的 UA 标识。

## 最佳实践

1. **Emby Server + 302**：最推荐组合，零带宽、高速度
2. **Jellyfin + 302**：同样支持，配置方式相同
3. **Kodi + 302**：Kodi 20+ 对 302 + Range 支持完善
4. **Infuse + 302**：Infuse 对 302 支持不完善，建议在 `ForceProxyUaTokens` 中加入 Infuse 的 UA

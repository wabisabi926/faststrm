# 功能详解 - 生活事件监控

## 概述

生活事件监控是 Fast Strm 的实时同步能力：每 30 秒轮询 115 网盘生活事件，自动同步本地 STRM，无需等待定时全量扫描。

## 启用监控

进入「设置」→「生活监控」：

1. 勾选「启用监控」
2. 选择要监控的 115 账号
3. 配置路径映射
4. 保存后会自动开始首次拉取

[📸 此处需截图：生活监控设置卡片]

## 路径映射

监控需要路径映射来知道「网盘路径变动 → 哪个本地 STRM 目录受影响」：

```json
[
  {
    "account": "我的115",
    "cloudPath": "/电影",
    "localPath": "/app/data/strm/电影"
  },
  {
    "account": "我的115",
    "cloudPath": "/电视剧",
    "localPath": "/app/data/strm/电视剧"
  }
]
```

- 只有映射的 `cloudPath` 下的变动才会被处理
- 网盘根目录变动（不在映射内）会被忽略

## 四类事件

### 创建事件（create）

**场景**：115 网盘新增文件/文件夹（上传、转存、离线下载完成）

**处理**：
1. 解析文件路径（通过 cid 反查）
2. 在路径映射范围内 → 生成 STRM
3. 文件夹事件 → 递归生成所有子文件 STRM
4. 写入 filePathDb
5. 触发 Emby 刷新（防抖）

### 删除事件（remove）

**场景**：115 网盘删除文件/文件夹

**处理**：
1. **熔断检查**：单次轮询删除数 >100 或占比 >50% → 跳过并告警
2. 通过 fileId 在 DB 反查本地 STRM 路径
3. STRM 移入回收站（7 天）
4. 删除 DB 记录
5. 清理空目录
6. 触发 Emby 刷新

> **熔断保护**：防止 115 API 返回异常导致大规模误删。如果误触发，可在 `.trash/` 恢复。

### 重命名事件（rename）

**场景**：115 网盘重命名文件/文件夹

**处理**：
1. 通过 fileId 反查旧路径
2. 删除旧 STRM
3. 用新名称重新生成 STRM
4. 更新 DB

### 移动事件（move）

**场景**：115 网盘移动文件/文件夹

**处理**：
1. 解析新旧路径
2. 判断移动类型：
   - **映射内移动**（新旧路径都在映射目录）：删除旧 STRM，在新位置生成
   - **移入映射**（旧路径不在映射，新路径在映射）：在新位置生成 STRM
   - **移出映射**（旧路径在映射，新路径不在映射）：删除旧 STRM + 空目录
3. 更新 DB

> **文件事件兜底**：文件移动（非文件夹）时，由于无法通过 cid 递归，会按文件名递归搜索本地 STRM 兜底清理。

## 首次拉取模式

`firstPullMode` 控制首次启用监控时如何处理历史事件：

| 模式 | 行为 | 适用场景 |
|------|------|----------|
| `latest` | 只拉取最新一批事件 | 默认，避免重复生成 |
| `all` | 拉取所有历史事件 | 需要补齐遗漏 |
| `last` | 从上次断点继续 | 重启后恢复 |

## 断点恢复

`lifeMonitorState.json` 记录每个账号的最后处理时间戳：
- 容器重启后从断点继续，不会遗漏事件
- 如果断点超过 7 天（115 历史保留期），自动切换到 `latest` 模式

## 路径解析缓存

3 层缓存避免重复 API 调用：

| 层级 | 存储 | TTL | 用途 |
|------|------|-----|------|
| L1 | `lifeIdPathCache.json` | 永久 | cid → path 映射 |
| L2 | 内存 Map | 进程生命周期 | 单次轮询内复用 |
| L3 | 115 API | - | 兜底反查 |

## API 降级

115 生活事件 API 有两个端点：
- **iOS API**（`/ios/...`）：返回结构更完整，但偶发 405
- **Web API**（`/web/...`）：稳定，但某些字段缺失

监控自动降级：iOS 405 → 切 Web API，用户无感。

## 移动/重命名模式

`moveMediaMode` 控制移动事件的处理方式：

| 模式 | 行为 |
|------|------|
| `recreate` | 删旧 STRM + 在新位置重新生成（默认） |
| `local_move` | 本地移动 STRM 文件（更快，但路径映射必须精确） |

## 与全量扫描的互斥

全量扫描任务执行时会调用 `suspendMonitorForFullScan(account)` 暂停监控，避免：
- API 竞争（全量扫描和生活监控同时调 115 API）
- DB 竞争（同时写 filePathDb）

全量扫描完成或异常后，`finally` 块调用 `clearMonitorSuspend(account)` 恢复。

> 如果全量扫描卡住，监控最多暂停 10 分钟（`FULLSCAN_TIMEOUT_MS`），超时自动恢复。

## 1. 修复内容

### F1 外部媒体源认证头（P1）

- `resolveRedirectChain` 仅发送 `User-Agent`、`Accept`，移除 `X-Emby-UserId` 注入；
  删除原 `buildForwardHeaders`。
- `followRedirectClient.CheckRedirect` 跨主机跳转时兜底清除
  `Authorization`、`Cookie`、`X-Emby-Token`、`X-MediaBrowser-Token`、`X-Emby-UserId`。
- 新增 `proxy_media_headers_test.go`：覆盖首跳、跨主机 302、同主机保留、UA 透传。

### F2 路径前缀 LIKE 转义（P2）

- `escapeLike` 上提到 `internal/service/db/like.go`，新增 `literalPrefixPattern`。
- 六处统一 `LIKE ? ESCAPE '\'`：文件/目录的更新、删除、`CountFilesByPrefix`、
  `ListSnapshotByAccount`；快照同时补 `normalizeDbPath`。
- `substr` 偏移仍使用原始前缀 rune 长度，未受转义影响。
- 新增 `filepath_repo_like_test.go`：覆盖 `_`、`%`、`\` 与相邻子树零误伤。

### F3 SSE 锁外读取（P2）

- `Subscribe`/`Unsubscribe` 在锁内保存 `total := len(s.subscribers)`。
- 新增 4 goroutine × 100 次并发订阅/退订用例。

### P1-3 刷库请求风暴

- `RefreshByPath` 防抖键从文件路径改为所在目录；同一目录只保留一个 timer。
- 刷新父目录使用 `Recursive=true`，覆盖其下新增/删除项。
- 新增 4 并发上限 + 30s 排队超时，避免一次全量任务同时打向 Emby。
- 新增 `refresh_debounce_test.go`：50 个文件 / 2 个目录 → 仅 2 次 Find + 2 次 Refresh。

### P1-4 优雅退出与遗留状态

- `Runtime.CancelAll` / `WaitAll`：进程退出时取消并等待运行中任务（20s 上限）。
- `server.Shutdown`：停止调度器、生活监控、Emby 反代，触发 go-zero HTTP 停服。
- 主进程 SIGINT/SIGTERM 与托盘退出统一走排空流程；Unix 强杀窗口放宽到 25s。
- 启动时 `TaskHistoryRepo.MarkInterrupted` 将上次硬退出遗留的 running/pending 记录标记为失败。

### P2 小修批次

- P2-2：日志级别支持 `FASTSTRM_LOG_LEVEL` 环境变量，非法值回退 info。
- P2-3：`handler/strm.go` 与 embyproxy streamClient 增加 10s 拨号/TLS 握手超时、`MaxConnsPerHost=16`。
- P2-4：`CompleteExecution` 失败后重试一次并写 Error 日志。
- P2-5：`health.go` 的版本兜底从 `v1.5.4` 改为 `dev`。
- P3-1：`WriteStrmFile` 在 rename 前调用 `tmp.Sync()`；Bootstrap 启动纳管时清理超过 24h 的 `.strm.tmp-*`，并补回归用例。
- `migrateManagedPaths`：失败时除 Warn 日志外写入生活事件日志，明确“文件已移动、下次启动纳管修复”；不做事务补偿。

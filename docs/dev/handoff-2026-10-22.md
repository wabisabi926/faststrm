## 1. 已完成的改动（本会话）

### 1.1 设置留空语义 + 热生效

- UA / STRM 扩展名 / 强制代理格式：显式留空保持空，不再写回默认值；运行时分别由
  `Settings.EffectiveUserAgent()` / `Settings.EffectiveStrmExtensions()` 和内置格式兜底。
- 删除前端保存后的默认值回填与「已恢复默认」toast。
- `StrmOptions` 改为 `Settings func() *model.Settings`；服务器用 `atomic.Pointer[model.Settings]`
  保存快照，设置保存后更新，STRM 播放/诊断不再读启动时 `cfg.Settings`。
- `client115.Client` 增加线程安全 `SetUserAgent`/`UA()`；设置保存后热更新。
- `range_limiter` 按「账号+上限」建池，修改并发上限后新请求立即生效。
- 清理目录的保留扩展名、生活事件辅助文件判断改用 `EffectiveStrmExtensions`。
- 后端测试已更新并通过：`internal/handler`、`internal/service/store`。

### 1.2 设置保存范围收敛

- 常规设置只提交常规/STRM/下载/限流字段。
- 清理页只提交 `{cleanup}`，不再整份 settings 覆盖其他模块。
- 生活监控统一走 `/api/lifeMonitor` 的 `updateConfig`（后端校验账号 + `Monitor.Refresh()`）。
- 账号下拉过滤为 115；移除监控账号时同步清理对应路径映射。
- `/api/settings` POST 移除了 Emby/Telegram 覆盖块；生活监控块保留但增加账号校验。
- `MonitorSettingsTab` 只保留「保存并应用监控」一个按钮。
- `firstPullMode` 已实现：无持久化游标时 `latest`=now-300、`all`=1、`last`=now-300；
  有游标时始终续传。UI 文案还没补「仅首次无游标时生效」。

### 1.3 路径映射与目录选择器

- `matchPathMapping` 两侧统一 `normalizeCloudPath`，修复「/电影」导致事件全部跳过。
- 监控页路径 placeholder 改为「如 电影（有无 / 均可）」。
- 本地目录选择保留 `C:\`，不再裁成 `C:`。
- `listChildren` 对文件返回 code 400「路径不是目录」。
- 云目录选择器/本地目录树只允许目录节点被选中。
- 任务保存校验 `TargetPath` 必须是绝对路径，且已存在时必须是目录。

### 1.4 任务启动/取消与历史

- `ExecuteTask` 增加可选 `onStarted` 回调；HTTP 层等待真实拿到账号锁后返回，
  blocked 时返回 409，不再假报「已启动」。
- 执行器在扫描后、写 STRM 循环内、最终完成前检查取消；取消后收敛为 cancelled，不覆盖为 completed。
- 取消未运行任务返回 `success=false, reason=not_running`；前端显示提示。
- `TaskHistoryQuery` 支持 `executionId` 精确查询；`log-detail` 改为按 executionId 查询，旧记录不再误报不存在。
- 历史页支持 `before` 游标「加载更多」，统计卡改为「已加载记录」。
- 新增任务弹窗补错误 toast；定时保存统一读取后端 `error`。

### 1.5 STRM 历史与缓存

- 任务记录移除重复的「STRM 操作」页签；生活事件页保持原样，旧 `/history?tab=strm` 自动跳到 `/life-events`。
- 新增 `StrmHistoryTab`：列表、stats、类型筛选、详情弹窗，接入 `/api/history/strm`、
  `/stats`、详情字段。
- 播放诊断页增加「清除直链缓存」按钮，调用 `/api/strm/cache/clear`。

### 1.6 清理明细

- `scan-normalize` 透传 `unmanagedStrms`；未托管明细不再恒为空。
- 后端 `MissingStrm` 增加 `mediaExtension`；前端缺失时从 `cloudRelPath` 推导。
- 移除未使用的组合清理前端代码（`handleDeleteAndRegenerate` / `handleCombinedResult`）。

### 1.7 账号状态与账号告警

- `/api/account/status?deep=true` 改为有界并发（3）探测，单个 8s；探测完成后才生成 results。
- 前端账号状态改为合并 map，单号刷新不再清空其他账号；`deepResults` 不再需要，
  `data` 变化会重新检测。
- 账号告警配置接入：
  - 监控侧 Cookie 失效通知受 `Telegram.AccountAlerts.Enabled/OnError` 控制；
  - `VerifyAccount` 恢复时按 `OnRecover` 发通知；
  - 主动巡检按状态跃迁发送失效/恢复通知。
- 注意：默认 `AccountAlerts.Enabled=false`，因此默认不再发送 Cookie 失效通知；
  这是按 UI 配置语义来的，若希望默认开启需调整默认值。

### 1.8 Telegram

- 移除 Dispatcher 把 `Telegram.WebhookURL` 当通用出站 Webhook 的错误用法；
  删除 `internal/service/notify/webhook.go` 及测试。

- 轮询徽标按 `pollingStatus.message` 显示「轮询中 / Webhook / 未运行」；保存后刷新状态。
- 前端填写 Webhook URL 自动取消自动轮询；勾选自动轮询自动清空 Webhook URL。

3. 如果希望保持 `main` 干净，也可以不提交，直接依赖工作区；但风险是后续操作误重置/误清理。
4. 不要推送；当前没有要求发布。

## 5. 关键设计决策（后续不要改回去）

- 留空语义：**配置保持空 + 运行时兜底默认**，不是“留空=关闭”。
  例外：附带下载扩展名空=不下载；强制代理 UA 空=全部 302。
- 媒体挂载路径功能已删除；`LifeMonitor.MediaMountPath` 字段保留但无 UI。
- Telegram `WebhookURL` 只表示 Telegram 回调本服务的地址，不能当通用出站 Webhook。
- Webhook 与 AutoPolling 互斥；保存 Webhook 时必须配置 secret。
- `SyncDeleteDryRun` 只在“同步删除未启用且字段缺失”时迁移为 true；
  已启用同步删除的老用户保持原值，避免升级后突然停止删除。
- Emby/Telegram 只允许各自专用接口写入；通用 `/api/settings` 不再覆盖它们。

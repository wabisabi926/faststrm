# 功能详解 - STRM 生成

## 概述

STRM 生成是 Fast Strm 的核心功能：扫描 115 网盘目录树，为每个媒体文件生成本地 `.strm` 文件，配合 Emby/Kodi 实现云盘资源本地化播放。

## 任务配置

### 创建任务

进入「任务管理」→「新建任务」：

| 字段 | 必填 | 说明 |
|------|------|------|
| 账号 | ✓ | 选择已添加的 115 账号 |
| 云端目录 | ✓ | 115 网盘源路径，如 `/电影` |
| 本地目录 | ✓ | STRM 保存子目录，如 `电影` |
| STRM 前缀 | - | 任务级覆盖（留空用全局） |
| 定时任务 | - | cron 表达式，如 `0 3 * * *` |
| 是否生成 STRM | - | 关闭则只下载文件不生成 STRM |
| 下载扩展名 | - | 任务级覆盖 |
| STRM 扩展名 | - | 任务级覆盖 |

> 任务级「删除多余文件」已下线；孤儿清理统一由全局「孤儿 STRM 清理」+ 托管所有权处理，见 [STRM 清理对账](STRM-清理对账)。

[📸 此处需截图：新建任务对话框]

### STRM 扩展名默认值（v1.1.1 新增 iso）

| 类型 | 格式 |
|------|------|
| 常规视频 | mp4, mkv, avi, mov, rmvb, webm, flv, m3u8, ts, m2ts |
| 音频 | mp3, flac, wav, aac, ogg, m4a |
| 原盘 | **iso**（v1.1.1 新增蓝光原盘支持） |

### ISO 原盘 STRM 格式

对于 `.iso` 原盘文件，生成的 STRM 采用**双扩展名**：

```
源文件: /电影/2024/星际穿越.iso
            ↓
STRM:  /电影/2024/星际穿越.iso.strm
内容:  http://服务器:8090/api/strm?account=xxx&pickcode=xxx&file_name=星际穿越.iso
```

为什么双扩展名？Emby/Jellyfin 看到 `.iso.strm` 就知道"这是一个 ISO 原盘的 STRM 代理"，播放时会按原盘模式（支持菜单、章节、音轨切换）而不是普通视频模式。

### STRM 文件名规则

文件名固定为 `{stem}.strm`（iso 自动变 `{stem}.iso.strm`），不再支持自定义文件名模板。

> **v1.5.5 起自定义 URL / 文件名模板已下线**：老配置首次读取会备份为 `settings.json.templates-v1.*` 后清空；手工写回 `settings.json` 也会在读取/保存时被清空。

**v1.2.3+ 统一 STRM 模式**：
- `strmPrefix = http://服务器:8090`（不含 `/api/strm`，前端自动追加）
- STRM 内容：`http://服务器:8090/api/strm?account=xxx&pickcode=xxx&file_name=xxx`
- 播放时 faststrm 接收请求 → 走[智能路由策略](STRM-路由策略)决策；STRM 层默认 302 直连 CDN，原盘格式的代理流处理在 Emby 反代层
- **依赖 pickcode**：必须有 `pickcode` 才能生成有效 STRM

> **v1.2.3 架构变更**：旧版 `enable302=false` 的 OpenList 直链模式已废弃（不再生成非 query URL）。所有 STRM 统一经过 faststrm 路由层，获得 force-proxy、并发限流、可达性预检等能力。

### 文件名非法字符清理

115 云端允许、但本地文件系统（尤其是 Windows / SMB 共享）不允许的字符，会在生成 STRM 时被自动替换。**目录名与文件名都适用**，事件生成与全量生成使用同一套规则：

| 原字符 | 替换为 | 说明 |
|---|---|---|
| `:` | `：`（全角） | 保留片名可读性，不变成下划线串 |
| `<` `>` `"` `|` `?` `*` `\` | `_` | Windows 非法字符 |
| 控制字符（0x00–0x1F） | `_` | 乱码文件名常见 |
| 段尾的空格 / 点 | 去掉 | Windows 会静默截断，导致每次任务都重写同一个文件 |

示例：

```
115: /电影:合集/流浪地球2:2023.mkv
本地: /media/电影：合集/流浪地球2：2023.strm
```

> 云端路径（数据库、STRM 内容里的 `file_name`）**不做替换**，只在落盘时替换，因此不影响播放与清理对账。

### 路径映射

任务通过 `云端目录` + `本地目录` 建立映射：

```
115: /电影/2024/小王子.mkv
          ↓
本地: /app/data/strm/电影/2024/小王子.mkv.strm
```

- `本地目录` 是 `exportDir`（STRM 根目录）下的子目录
- 完整本地路径 = `{exportDir}/{本地目录}/{相对云端路径}`

### 定时任务

cron 表达式示例：

| 表达式 | 含义 |
|--------|------|
| `0 3 * * *` | 每天凌晨 3 点 |
| `0 */6 * * *` | 每 6 小时 |
| `0 0 * * 0` | 每周日凌晨 |
| 留空 | 仅手动执行 |

> 账号级令牌桶限流：同一账号的多个任务会自动排队，避免 115 API 频控。

## 任务执行流程

```
任务触发
  ↓
账号探测 + 读取任务/全局设置
  ↓
扫描云端（cur=0 全量清单，异常回退逐目录）
  ↓
孤儿预扫清理（托管核对 + 云端复核 + 回收站）
  ↓
生成/更新 STRM + 托管登记
  ↓
下载关联文件（可选，幂等）
  ↓
写回 filePathDb
  ↓
Emby 媒体库刷新（防抖）
  ↓
TG 通知
```

> 任务与生活事件共用同一套 STRM 内容生成（`strm.BuildContent`）与托管登记；清理不会直接物理删除，详见 [STRM 清理对账](STRM-清理对账)。

### 任务模式说明（v1.5.1）

FastStrm **没有「全量 / 增量」两种任务模式**，只有一种：

- 每次「启动」都会**完整扫描**任务指定的云端目录
- 已存在且内容未变的 STRM **不会重写**（内容比对 + `overwriteMode`）
- 新增/变化的文件正常处理（包括新加的字幕、nfo、海报）

所以「跑一次任务」在效果上就是增量：首次用于建立索引，之后用于补齐新增内容。
不需要为「全量还是增量」纠结，也不存在必须先跑全量才能用增量的限制。

### 可读任务 ID（v1.5.1）

新建任务时，任务 ID 由时间戳改为「账户-目录名」：

```
aliyun-电影      ← 账户 aliyun + 云端目录 /媒体/电影
```

- 特殊字符会被清洗为 `-`，超长按 UTF-8 安全截断（≤48 字节，防止 Telegram callback_data 超限）
- 同名冲突自动追加 `-2`、`-3`
- **旧任务 ID 不受影响**，仍可正常使用

### 字幕 / 元数据自动同步（v1.5.1）

生活事件监控开启后，网盘里**后续新增**的字幕（srt/ass/sub）、nfo、海报（jpg/png）会：

```
115 新增文件事件 → 识别 DownloadExtensions → 下载到对应本地目录
```

- 扩展名同时出现在「STRM 扩展名」时优先按视频处理（不会把视频当字幕下载）
- 单文件上限 200MB；已存在且大小一致跳过；先写 `.part` 再原子改名
- 不需要重跑任务，也不需要等下一次定时同步

> 如果没开生活事件监控，也可以在网盘加字幕后手动跑一次任务，效果相同。

## pickcode 获取机制

302 模式下，`pickcode` 是 STRM 的核心凭证（115 文件唯一标识）。获取方式因生成途径而异：

### 生活事件生成

115 生活事件 API 直接返回 `pick_code` 字段，100% 可靠：

```
115 → life event → pick_code → generateStrmContent → 写入 STRM
                                                → upsertFilePathEntry（存 DB）
```

### 全量扫描生成

全量扫描走 115 目录递归清单（`cur=0`）或逐目录扫描，清单条目直接包含 `pick_code`；不再需要 `exportDirParse`，也不需要从 `filePathDb` 反查。

```
全量扫描 → 云端条目 pick_code
         → 生成 STRM
         → 写入 filePathDb（供播放/删除/移动反查）
```

只有 pickcode 缺失/非法的文件会跳过，并在任务日志中输出原因。首次全量扫描即可正常生成，无需先跑一轮补 DB。

### 兜底保护

当 `pickcode` 缺失时：

1. `generateStrmContent` 返回空字符串 + `console.warn` 警告
2. 调用方（`enqueueForAccount` / `strmCleanup`）跳过写入
3. `syncStrmText` 防御性检查，拒绝写入空内容
4. 日志中可看到：`[STRM] pickcode 缺失，跳过生成`

## STRM 文件格式

每行一个 URL，UTF-8 编码：

```
http://192.168.1.100:8090/api/strm?account=我的115&pickcode=xxxx&file_name=小王子.mkv
```

- `account`：账号名
- `pickcode`：115 文件唯一标识
- `file_name`：文件名（用于 Content-Disposition 和大文件判断）

## URL 编码

STRM 内容统一使用 pickcode 式 URL，`account` 与 `file_name` 参数默认做百分号编码（空格为 `%20`，不是 `+`）。

设置页「URL 编码」开关（`enablePathEncoding`）默认开启。关闭后参数原样写入 URL；文件名含 `#`、`&`、`?`、空格等字符时会破坏 URL 解析，仅在确有需要时关闭。

## 孤儿清理

任务执行时的孤儿清理统一走托管所有权：

- 只处理已在 `managed_strms` 登记的 STRM
- 删除前复核文件指纹与云端状态
- 删除移入 `.faststrm-trash` 回收站，保留 7 天

详细规则、阈值与恢复方式见 [STRM 清理对账](STRM-清理对账)。

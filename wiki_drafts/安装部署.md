# 安装部署

## Docker 部署（推荐）

### docker-compose

```yaml
version: "3.9"
services:
  faststrm:
    image: wabisabi926/faststrm:latest
    container_name: faststrm
    ports:
      - "8090:8090"   # Web UI + API + /api/strm
      - "8097:8097"   # Emby 反向代理（UI 里 ProxyPort 填 8097 时生效）
      # 容器侧端口必须等于 UI 里的「反代监听端口」；宿主机侧端口被占用时可以换，
      # 例如 "18097:8097"，客户端统一用宿主机端口访问即可
    volumes:
      - ./config:/app/config
      - ./data:/app/data
      - /path/to/your/strm:/app/data/strm  # STRM 文件输出目录
    environment:
      - TZ=Asia/Shanghai
      - APP_ENV=prod
      - SERVER_HOST=0.0.0.0
      - SERVER_PORT=8090
    restart: unless-stopped
```

```bash
docker-compose up -d
```

> 不需要 Emby 反向代理时，`8097:8097` 这行可以删掉，不影响主功能。

### docker run

```bash
docker run -d \
  --name faststrm \
  -p 8090:8090 \
  -p 8097:8097 \
  -v ./config:/app/config \
  -v ./data:/app/data \
  -v /path/to/your/strm:/app/data/strm \
  -e TZ=Asia/Shanghai \
  -e APP_ENV=prod \
  -e SERVER_HOST=0.0.0.0 \
  -e SERVER_PORT=8090 \
  --restart unless-stopped \
  wabisabi926/faststrm:latest
```

## 端口说明

| 端口 | 映射写法 | 用途 |
|------|---------|------|
| 8090 | `-p 8090:8090` | Web UI + API + STRM 路由（单端口，前端 SPA 和 API 同源） |
| 8097（可选） | `-p 8097:8097` | Emby 反向代理 — 拦截 PlaybackInfo 强制 STRM DirectPlay，解决 Emby for Kodi ISO/STRM 转码问题 |

> 💡 只映射 8090 就能正常使用。要启用 Emby 反向代理，必须**额外映射反代端口**：
> 在「设置 → 通知中心 → Emby」把「反代监听端口」填成 8097（默认值），并保证 compose / `docker run` 里有 `8097:8097`。
> 💡 **容器侧端口必须等于 UI 里的「反代监听端口」**。容器内监听的是配置里的 `proxyPort`，
> 写成 `8097:8098` 这种容器侧错位的映射，容器里没有进程监听 8098，客户端自然连不上。
> 宿主机侧端口可以不同（如 `18097:8097`），客户端用宿主机端口访问；反代会按请求的 Host 端口改写 `system/info`。
> 💡 改了反代端口（比如改成 9000），要同时改映射的容器侧为 `9000:9000`，再 `docker compose up -d` 重建容器。
> 💡 详见 [Emby 集成 - 反向代理](Emby集成#emby-反向代理v118-推荐开启)。

### Docker 里开反代的三个坑

1. **Emby 地址不能用 `127.0.0.1`**
   容器里的 `127.0.0.1` 是 FastStrm 自己，不是宿主机。Emby 装在宿主机上时，
   「Emby 服务器地址」要填宿主机的局域网 IP（如 `http://192.168.1.10:8096`）；
   Emby 也在同一个 compose 网络里时，可以填服务名（如 `http://emby:8096`）。
2. **STRM 前缀要用宿主机地址**
   `strmPrefix` 填 `http://<宿主机IP>:8090`，不要填 `localhost` 或容器名 ——
   Emby（可能在另一个容器/另一台机器）和播放器都要能访问到。
3. **容器侧映射和 UI 配置必须一致**
   先改 UI 端口 → 再改 compose 的容器侧端口 → 重建容器。只改一处会出现「反代启动成功但客户端连不上」
   或「端口被占用，反代启动失败」（启动日志里能看到 `[EmbyProxy] 启动中: 0.0.0.0:8097`）。

## 目录挂载

| 目录 | 容器路径 | 用途 |
|------|---------|------|
| `./config` | `/app/config` | 配置文件（config.json, settings.json, account.json, tasks.json） |
| `./data` | `/app/data` | 数据文件（SQLite 数据库、删除历史、生活事件日志、运行日志） |
| STRM 目录 | `/app/data/strm` | STRM 文件输出路径 |

## 配置文件说明

| 文件 | 用途 | 敏感字段 |
|------|------|---------|
| `config.json` | 登录凭据 | 密码 salt+SHA-256 |
| `settings.json` | 全局设置 | apiKey/botToken AES-256-GCM |
| `account.json` | 115 账号信息 | cookie/token AES-256-GCM |
| `tasks.json` | 同步任务定义 | - |

> v1.5.2 起，新安装首次启动不再生成随机密码文件：打开 Web 页面进入初始化页，自行创建管理员账号。已有安装继续使用原密码，不会重复初始化。

## 首次初始化

1. 浏览器打开 `http://localhost:8090`
2. 首次启动会进入「创建管理员账号」页面
3. 设置用户名和至少 8 位密码，创建后进入后台

Docker / 飞牛 / 无界面部署也可以直接通过环境变量初始化，跳过 Web 向导：

```bash
FASTSTRM_ADMIN_USERNAME=admin
FASTSTRM_ADMIN_PASSWORD=至少8位密码
```

> 旧版本生成的 `initial-admin-password.txt` 仅为升级兼容保留；完成初始化或改密后会自动清理。

## 反向代理（可选）

如需公网访问，建议在前面加 Nginx/Caddy：

```nginx
server {
    listen 443 ssl;
    server_name strm.yourdomain.com;

    location / {
        proxy_pass http://127.0.0.1:8090;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

> 💡 STRM 路由需要正确传递客户端 IP（用于局域网代理判断），务必配置 `X-Forwarded-For` 头。
> 💡 想让 Emby 反代端口（8097）也走域名/HTTPS，另建一个 `server` 指向 `127.0.0.1:8097`，
> 并透传 `X-Forwarded-Port` / `X-Forwarded-Proto`；反代会按这两个头改写 Emby `system/info` 里的端口，
> 漏配时 Emby Web 可能连到错误端口。

## 构建架构

FastStrm v0.9.1 采用纯 Go 架构，**不再依赖 Node.js 和 Nginx**：

| 组件 | 技术栈 |
|------|--------|
| 后端 | Go + go-zero，单二进制运行 |
| 前端 | Vite + React SPA，通过 `go:embed` 嵌入二进制 |
| 数据库 | SQLite（本地嵌入式） |
| 配置存储 | JSON 文件加密存储 |
| 容器基础 | `alpine:3.19`，无 Node.js/Nginx |

GitHub Actions 自动构建以下平台：

- `linux/amd64`（x86_64）
- `linux/arm64`（Apple Silicon / 树莓派 4 / CoreELEC）
- `windows/amd64`（Windows 服务器）
- `darwin/arm64`（macOS Apple Silicon）

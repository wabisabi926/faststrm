# 删除同步

当你在 Emby 中删除媒体时，Emby 会推送 `library.deleted` 事件。faststrm 收到后自动删除本地 STRM + 关联文件 + DB 记录。

---

## 前置条件

1. Emby 已配置 Webhook（`http://faststrm地址:8090/api/emby/webhook`）
2. Emby Webhook 勾选了「项目删除」事件
3. faststrm 的「Emby 通知」页面已填写 Emby URL 和 API Key
4. 已在「删除同步」卡片启用同步并配置路径映射

---

## 启用步骤

1. 进入「Emby 通知」页面
2. 找到「删除同步」卡片
3. 勾选「启用删除同步」
4. **首次强烈建议勾选「试运行模式」**（只记日志不实际删除）
5. 配置路径映射（见下方）
6. 保存

### 试运行模式

首次配置时务必开启：

- 只记录日志，不实际删除文件
- 日志会显示 `[试运行] 模式，仅记录不删除: <路径>`
- 确认路径映射正确后再关闭

---

## 路径映射

告诉 faststrm「Emby 中的这个路径」对应「115 网盘的哪个路径」：

```json
[
  {
    "embyPath": "/app/data/strm/电影",
    "cloudPath": "/电影",
    "account": "我的115"
  }
]
```

| 字段 | 说明 | UI 控件 |
|------|------|---------|
| `embyPath` | Emby Webhook 推送的 `Item.Path` 前缀 | 📁 本地文件夹选择器 |
| `cloudPath` | 115 网盘对应路径 | 🗄️ 云盘目录选择器（需选特定账号） |
| `account` | 指定清理 filePathDb 的账号 | 下拉选择器，从已配置的 115 账号中选取 |

> 💡 **v0.8.1 增强**：
> - Emby 路径前缀支持本地文件夹选择器（📁），无需手动输入路径
> - 115 网盘路径前缀支持云盘目录选择器（🗄️），仅当选定特定 115 账号时启用；账号为「遍历全部账号」时禁用
> - 账号字段从手动输入改为下拉选择器，自动读取已配置的 115 账号列表

### 路径映射示例

假设你的配置：
- Emby 媒体库路径：`/app/data/strm/电影`
- 115 网盘目录：`/电影`
- 115 账号：`我的115`

当你在 Emby 删除「电影/2024/小王子.mkv」时：
1. Emby 推送 `Item.Path = /app/data/strm/电影/2024/小王子.mkv`
2. faststrm 匹配 `embyPath` 前缀，截取后缀 `2024/小王子.mkv`
3. 拼出网盘路径：`/电影/2024/小王子.mkv`
4. 在 filePathDb 中查找对应 pickcode

## 决策链

```
Emby library.deleted 事件
  ↓
检查启用状态 → 未启用则跳过
  ↓
检查 Path 字段 → 缺失则跳过
  ↓
白名单匹配（路径前缀）→ 不匹配则跳过
  ↓
去重检查（60 秒窗口，防生活监控重复）→ 命中则跳过
  ↓
路径映射（路径段感知）→ Emby 路径 → 网盘路径
  ↓
防误删 1：STRM 文件/目录存在才处理
  ↓
防误删 2：Movie/Episode 标题校验
  ↓
试运行检查 → 是则只记日志
  ↓
按类型删除：
  Movie/Episode → 删 STRM + 关联字幕/nfo/图片（文件级物理删除）
  Season → 删整季目录（目录级物理删除）
  Series → 删整剧目录（目录级物理删除）
  ↓
防误删 3：目录文件数 ≤ 100 才执行
  ↓
更新 filePathDb
  ↓
写删除历史 + TG 通知
```

---

## 三道防误删保护

| 防线 | 说明 |
|------|------|
| **防误删 1** | STRM 文件/目录不存在则跳过（可能已被生活监控处理） |
| **防误删 2** | Movie/Episode 标题必须匹配 STRM 文件名，不匹配拒绝删除 |
| **防误删 3** | 整季/整剧目录文件数 ≤ 100 才执行（防止误删整个媒体库） |

---

## 去重机制

生活监控和 Emby Webhook 可能同时触发同一文件的删除：

```
场景：
1. 用户在 115 网盘删了文件
2. 生活监控检测到 → 删 STRM → Emby 发现 STRM 没了 → 推 library.deleted
3. 60 秒窗口内，Emby 的删除事件会被自动跳过
```

---

## 删除机制

所有 STRM 删除操作均为**直接物理删除**（`fs.unlinkSync` / `fs.rmSync`），不经过回收站：

- **文件级删除**：STRM + 关联字幕/nfo/图片直接物理删除
- **目录级删除**：整季/整剧目录直接物理删除
- **不可本地恢复**：删除后无法从本地找回，可在 115 网盘恢复源文件后重新全量扫描生成 STRM

### 误删恢复

如果删除同步误删了文件：

1. 在 115 网盘客户端确认源文件是否存在
2. 若源文件存在，重新执行对应任务或全量对账即可重新生成 STRM

> 建议首次启用删除同步时开启「试运行模式」确认路径映射正确，避免误删。

## 删除历史

`data/syncDelHistory.json` 保留最近 200 条删除记录：

```json
[
  {
    "itemPath": "/电影/2024/小王子.mkv",
    "itemName": "小王子",
    "itemType": "Movie",
    "deletedAt": "2026-08-11T10:30:00.000Z",
    "deletedFiles": 3
  }
]
```

## 故障排查

### 删除同步不工作？

1. 确认 Emby Webhook 已配置并勾选「项目删除」
2. 确认 faststrm 的「删除同步」已启用
3. **首次建议开启试运行模式**，查看日志确认路径映射正确
4. 路径映射的 `embyPath` 必须与 Emby 推送的 `Item.Path` 完全匹配前缀

### 如何验证路径映射？

1. 开启试运行模式
2. 在 Emby 中删除一个测试文件
3. 查看 faststrm 日志，应显示：
   ```
   [试运行] 删除同步路径匹配成功: embyPath=/app/data/strm/电影, cloudPath=/电影, path=电影/测试.mkv
   ```
4. 如果日志显示「路径不匹配」，检查路径映射配置

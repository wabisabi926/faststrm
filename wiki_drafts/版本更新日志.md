## v1.0.8 · 2026-08-25 · [对比](https://github.com/wabisabi926/faststrm/compare/v1.0.7...v1.0.8)

> 📌 本版本已包含 v1.0.7 全部内容

Emby API 认证修复、详情获取三级回退策略、TG Bot 命令补齐。

### ⚡ 优化

#### Emby API 客户端
- 移除所有 API 请求中对 `API Key` 和 `ID` 的 `url.QueryEscape` / `url.PathEscape` 编码，直接拼接字符串，与 qmediasync 保持一致
- `GetItemDetail` 重构为三级回退策略：①优先使用缓存的有权限用户 → ②尝试所有可用用户（新增 `GetAllUsers` 方法）→ ③无用户上下文降级
- `GetItemDetailWithRetry` 重试次数从 4 增至 5，移除仅 404 重试限制（所有错误均触发重试），增加详细日志

#### Telegram Bot
- `BotCommandList` 添加 `/start` 命令

### 🐛 修复

- 修复 Emby API 因 URL 编码导致认证失败的问题（`API Key` 中的特殊字符被转义后无法通过认证）
- 修复 Emby 实例无 `EnableAllFolders=true` 用户时入库通知详情获取失败的问题
- 修复 TG Bot 缺少 `/start` 命令的问题

## v1.0.7 · 2026-08-25 · [对比](https://github.com/wabisabi926/faststrm/compare/v1.0.6...v1.0.7)

> 📌 本版本已包含 v1.0.6 全部内容

Telegram 通知代理支持、重试机制全面上线，生活事件监控可靠性增强，通知排版与 Emby 集成优化。

### ⚡ 优化

#### Telegram 通知
- Metadata 展示顺序改为业务优先级（账号 / 类型在前 → 路径 → 度量 → 简介 → 时间在后），不再按 UTF-8 字节序排序，重点信息一眼可见
- 批量合并通知「👤 账号:」半角冒号改为全角「👤 账号：」，与 `FormatMessage` 统一渲染层风格一致
- `/scan` `/cleanup` 命令直接打开 STRM 操作菜单（全量同步 / 清理孤儿），不再显示占位文本
- `/help` 帮助文本全面重写，按实际可用命令 / 主菜单结构 / 任务执行 / 监控启停分组说明
- STRM 创建 / 删除 / 移动 / 重命名通知改用统一的 `FormatMessage` 三段式渲染，字段顺序与样式保持稳定
- 任务完成 / 任务错误通知改用 `FormatMessage` 统一渲染，与其他通知风格一致

#### Emby 通知
- 播放停止 emoji 由禁止符号 `⛔` 改为标准停止符号 `⏹️`，与参考项目一致
- 播放通知 metadata 字段「进度」改为「播放进度」，语义更清晰
- 播放通知配图策略由 Backdrop（横版背景）优先改为只取 Primary（竖版海报），与播放进度文字搭配视觉更协调
- 入库 / 删除 / 播放通知模板全面改用统一的 `FormatMessage` 三段式渲染层（Title / Content / Metadata）

#### 通用
- 新增 `BuildPrimaryImageURL` 方法，专门用于需要竖版海报的场景（播放通知）；入库通知继续走 Backdrop 优先的 `BuildImageURLIfAvailable`

## v1.0.5 · 2026-08-24 · [对比](https://github.com/wabisabi926/faststrm/compare/v1.0.4...v1.0.5)

> 📌 本版本已包含 v1.0.4 全部修复内容

生活事件监控可靠性增强：删除事件增加熔断保护、新建文件夹处理、关联文件删除安全校验等。

### ✨ 新增

- 新增删除事件熔断保护：单次轮询删除事件超过 100 条或占比超过 50% 时，自动跳过本次所有删除操作，防止 API 异常返回大量删除事件导致大规模误删
- 新增「仅错误通知」开关：LifeMonitor 设置页开启后，正常的创建 / 删除 / 移动 / 重命名不推 Telegram，仅异常时推送

### 🔥 删除

- 彻底移除「硬删除」配置与 UI 开关：所有删除操作统一为物理删除（直接删除），不再生成 `.deleted.bak` 备份文件，统一行为避免混淆

### ⚡ 优化

- Emby webhook URL 复制支持 HTTP 环境降级处理
- 前后端硬删除配置统一，UI 与后端配置项一致

### 🐛 修复

- 修复新建空文件夹事件被误判为媒体文件、错误生成 STRM 的问题
- 修复关联文件删除可能误删非关联文件的问题（例如之前 `movie` 可能误删 `movie_trailer.mp4`，现已加扩展名与 remainder 双重校验）

## v1.0.0 · 2026-08-22 · [对比](https://github.com/wabisabi926/faststrm/compare/v0.9.9...v1.0.0)

生活事件监控完全对齐参考项目 p115strmhelper，STRM 生成 / 移动 / 重命名 / 删除的核心逻辑全面重写，稳定性与准确性大幅提升。

### ✨ 新增

- 新增四象限决策矩阵（普通目录↔媒体目录之间的创建 / 移动 / 删除 / 跳过），事件处理更精准
- 新增事件类型严格路由：按 115 事件类型分别走创建 / 移动 / 重命名 / 删除四条专属处理分支
- 新增 STRM 清理双阈值二次确认：超过 10 条直接拒绝、5–10 条需 UI 确认，防误删
- 新增 STRM 操作历史记录 API：可查看每次全量 / 增量 / 监控 / 重命名 / 移动的执行结果、耗时、错误详情
- 新增 60 秒通知合并器：同一账号同类型事件 60 秒内自动合并，避免通知刷屏
- 新增 STRM 生成黑白名单过滤（如自动跳过 `-trailer`、`sample`、`.cd2` 等非正片文件）
- 新增 STRM 删除时可选同步清理关联文件（.nfo / .jpg / .srt / .ass / .sub）
- 新增飞牛 fNOS 安装向导端口自定义配置

### ⚡ 优化

- 115 API：多 User-Agent 轮换池 + 429 自动切换 + 域名修正 + 分级超时（普通 30s / 慢操作 300s），更不容易被限流
- 302 直连路由：405 自动降级 + 二次 pickcode 检索 + 并发锁，播放成功率更高
- Emby 自动刷库：新增 10 秒防抖，避免频繁触发媒体库扫描
- SQLite：WAL 模式 + busy_timeout + 单连接，并发读写更稳定
- 数据库孤儿清理：分页扫描 + STRM 清理后立即触发，DB 与本地文件状态一致

### 🐛 修复

- 修复 STRM 路径映射丢失子目录的问题（4 处误用，STRM 会生成到父目录而不是映射目录）
- 修复 DB 提前覆盖旧路径，导致旧 STRM 被误判为「不存在」而无法正确删除的问题
- 修复 recreate 模式下受配置影响不生成新 STRM 的问题
- 修复四象限 OTHER_TO_MEDIA 场景旧 STRM 未清理、造成同名重复文件的问题
- 修复 rename/move fallback 逻辑导致新旧 STRM 并存的问题（失败直接返回错误，行为与参考项目一致）

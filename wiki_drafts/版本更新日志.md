## v0.8.2

`2026-08` · [与 v0.8.1 对比](https://github.com/wabisabi926/faststrm/compare/v0.8.1...v0.8.2)

### 📱 115 扫码登录（重大新增）

新增 115 网盘扫码登录能力，无需再手动 F12 抓 Cookie：

- 后端新增 3 个 API：`/api/account/qrcode/token`、`/api/account/qrcode/status`、`/api/account/qrcode/cookie`，封装 115 二维码 token 获取、状态轮询、Cookie 落地
- 前端 `AddAccountDialog` 新增「扫码登录 / 手动粘贴」切换 Tab，支持 7 种客户端类型（默认「支付宝小程序」，兼容性最好；选「115 网页」会踢掉网页登录）
- 二维码以 base64 直接渲染，60 秒倒计时，过期自动刷新；扫码成功后 Cookie 自动回填，已填账号名则自动提交并关闭对话框
- 后端 `115.ts` 新增 `getQrcodeToken` / `getQrcodeStatus` / `getCookieByUid` 三个方法，对齐 p115client `APP_TO_SSOENT` 客户端映射与状态码处理

### 🔄 账户状态 TG 通知闭环

新增 `telegram.accountAlerts` 配置块，账号异常 / 恢复自动推送：

| 字段 | 默认 | 说明 |
|------|------|------|
| `enabled` | false | 启用账户状态通知 |
| `onError` | true | 账号异常（Cookie 失效等）时通知 |
| `onRecover` | true | 账号恢复时通知 |
| `expiryWarningDays` | 1 | Cookie 过期前几天开始警告 |

- 新增 `/api/notify/alerts` GET/POST 接口读写配置
- TG 通知页面新增「账户状态通知」卡片，支持开关、异常/恢复选择、过期预警天数
- 与账号管理页面的「更新 Cookie」按钮形成闭环：**账号异常 → TG 推送 → 扫码更新 → 后端异步重检 → 恢复正常推送恢复通知**

### 🍪 更新 Cookie 对话框

账号管理页面针对状态异常的 115 账号显示「更新 Cookie」按钮：

- 点击后弹出 `UpdateCookieDialog`，复用 `QrCodeLogin` 组件扫码
- 扫码成功后调 `PUT /api/account` 更新 Cookie 字段
- 后端 `qrcode/cookie` 路由异步触发状态重检，让 TG 恢复通知能立即发出
- 无需删除重建账号，保留原有任务 / 监控 / 路径映射配置

### 🐛 STRM 生成路径修复（P0）

- 修复 `taskExecutor.ts` 在全量扫描时误加 `../data/` 前缀，导致 STRM 文件多一层目录、302 模式反查 pickcode 失败的漏洞
- 统一使用 `resolveDataDir` 解析路径，规范化 `filePathDb` 路径匹配
- 修复 `enable302=true` 模式下 `pickcode` 缺失仍生成错误格式 STRM 的问题，新增 4 层兜底保护：`generateStrmContent` 返回空串 + 调用方跳过写入 + `strmCleanup` 检查 + `syncStrmText` 防御性拒绝空内容

### 🔀 STRM 路由策略配置化

将以下硬编码常量迁移至 `settings.json → strm` 子项，可在 Web UI「设置」页面修改，**实时生效无需重启**：

| 配置路径 | 默认值 | 说明 |
|----------|--------|------|
| `strm.forceProxyUaTokens` | `["Infuse","VidHub","SenPlayer","SenPlayerHD"]` | 强制代理 UA 列表 |
| `strm.accountProxyConcurrencyLimit` | `8` | 单账号并发代理上限 |
| `strm.redirectCheckTimeoutMs` | `5000` | HEAD 预检超时(ms) |

- 缓存策略常量（`URL_CACHE_TTL` / `URL_CACHE_SIZE` / `REACHABLE_CACHE_TTL` / `REACHABLE_CACHE_SIZE`）保持内部常量不暴露
- 同步更新路由规则引擎说明：规则 0（pickcode 校验）→ 规则 1（mode 参数，仅私网）→ 规则 2（force-proxy UA）→ 规则 3（默认 redirect）→ 兜底降级

### 🎨 页面排版与行距统一

- 设置页面、TG 通知页面、Emby 通知页面全部从 Card 组件改为统一的 `border rounded-md p-5 space-y-5` section 风格
- 全局 `Label` 组件行高从 `leading-none`（~14px）优化为 `leading-6`（24px），解决所有表单行距过密问题
- 修复设置页面「清理与安全」Tab 缺失外层闭合标签导致的渲染异常

### ⚙️ 默认设置 / 用户设置分离逻辑归位 + admin 密码哈希修复

- **Docker 场景**：`.config/` → `config/` 的复制逻辑 **原本就存在于 [`docker-entrypoint.sh`](https://github.com/wabisabi926/faststrm/blob/main/docker-entrypoint.sh) L11-26 + [`Dockerfile`](https://github.com/wabisabi926/faststrm/blob/main/Dockerfile) L44**，无需在 TS 层重复编写。删除了之前误新增的 `ensureDefaultConfigFiles()` 冗余代码和 6 处调用点/import
- **本地开发（非 Docker）**：依赖原有兜底——`readConfig()` 文件不存在时自动创建 `admin/admin`（已哈希）；其他 3 个 JSON 不存在返回 `[] / {}`，完全可用
- **🐛 v0.8.2 修复首次部署 admin 登录失败漏洞**：docker-entrypoint.sh 原来只是 `cp`，`.config/.config.json` 中 `password=""` 直接拷到 `config/config.json`，`verifyPassword("admin","")` 会失败。现在 cp 完 config.json 后附带一段 node 脚本检测 `username=admin && !password`，自动写入 SHA-256 + salt 的 `admin/admin` 哈希，并复用/创建 `.salt` 文件（docker-entrypoint.sh L19-45）
- **只在目标文件不存在时才复制**，绝不覆盖已有用户配置

### 🧹 移除 .trash 临时目录

- 确认 `data/.trash` 目录在代码中已无任何引用（Grep 0 结果），属于历史遗留
- 删除 `data/.trash` 下所有垃圾文件及空目录，释放磁盘空间
- 相关清理逻辑已迁移到 `removeExtraFiles` + `deleteStrmDir(rootDirs)` 安全机制
- 同步清理文档：所有「移入 `.trash/` 回收站（7 天保留）」描述改为「直接物理删除」，并在 FAQ / 删除同步 / 清理对账 / 生活事件监控 / STRM 生成 等页面统一表述

### 🚀 生活监控自动启动

- 新增 `tryAutoStartMonitorsOnce()` 函数，进程内通过 `globalThis.__lifeMonitorsAutoStarted` 保证只执行一次
- 触发条件（同时满足）：
  1. 监控配置 `enabled = true`
  2. 监控账号列表 `accounts` 非空
  3. 对应账号凭据非空（115：`cookie` 有内容；openlist：`url / account / password` 齐全）
- 触发时机：懒加载触发——首次有用户访问监控相关页面 / 接口 / 状态时，由 `getLifeMonitorConfig()` 自动拉起
- 真正的 CK 有效性由首次 `oncePoll()` 轮询时自动检测，失败会将状态置为 `error`，不会死循环或阻塞
- 服务重启后无需用户手动点「启动」，符合用户日常使用习惯

### 🌐 文档与界面本地化

- 「Dry-run」在所有用户可见界面 / TG 通知 / 文档中统一改为「试运行」（代码变量 `dryRun` 保持不变）
- 同步翻译 docs/ 和 wiki_drafts/ 共 12 个文档文件

## v0.8.0

`2026-08` · [与 v0.7.0 对比](https://github.com/wabisabi926/faststrm/compare/v0.7.0...v0.8.0)

### 🐛 全量扫描与增量监控融合修复（P0/P1）

- `suspendMonitorForFullScan` 提前到 `tryEnterFullScan` 之后，消除监控与 `removeExtraFiles` 的竞态窗口
- `removeExtraFiles` 增加三层安全阈值（空数据 / 绝对数 >100 / 比例 >10% 跳过），防止 API 异常时误删
- `localPath` 统一 `path.resolve` 解析，移除 `../data/` 硬编码
- recreate 模式 DB 路径前缀更新移到创建成功之后，避免失败时 DB 与文件系统不一致
- `clearScanState` 移入 `finally` 块，避免扫描中断后状态残留
- 删除事件去重日志，避免 `appendLifeEventLog` 重复记录

### 🔧 低风险问题修复（P2）

- `runScan` finally 块补 `clearMonitorSuspend`，避免扫描异常时监控永久挂起
- `executeTask` 无下载但清理了多余文件时也刷新 Emby
- `buildFilePathEntriesFromTree` 用负值标记 `fileId`，避免与真实 115 file_id 冲突
- `taskExecutor` 全量扫描后写回 `filePathDb`，确保 302 模式反查 pickcode
- `deleteStrmDir` 新增 `rootDirs` 选项，删除后自动清理空父目录

### 🐛 任务日志查询修复

- `/api/taskLog/[taskId]` 增加历史记录回退查找，已执行但未运行的任务也能查看日志
- 前端 `goToLog` 支持 `executionId` 参数跳转历史模式

## v0.7.0

`2026-07` · [与 v0.6.0 对比](https://github.com/wabisabi926/faststrm/compare/v0.6.0...v0.7.0)

### 🚀 STRM 路由策略优化

- 默认策略从「代理优先」改为「302 优先」：faststrm 与 Emby Server 同机部署时避免双重中转
- 仅对 Infuse/VidHub/SenPlayer 等 seek 兼容性差的客户端强制代理
- 新增 115 单账号并发代理限流（阈值 8），超限自动切 302
- 新增真实文件大小识别：调用 115 download API 解析 `file_size` 字段
- 移除局域网强制代理与大文件阈值规则（默认 302 后无需区分）
- `urlCache` key 去掉 UA 维度，提升缓存命中率
- `hopByHop` 头列表提为模块顶层常量
- `?mode=redirect|proxy` 调试参数仅私网生效

### ✨ Emby 删除同步（移植自 samediasyncdel）

- 监听 Emby `library.deleted` 事件，自动删除本地 STRM + 关联文件 + 清理空目录 + 更新 filePathDb
- 路径映射：Emby 路径 → 115 网盘路径（路径段感知）
- 三道防误删保护：STRM 不存在跳过 / 标题校验 / 整季目录文件数 ≤100 才删
- 去重机制：60 秒窗口防止生活监控与 Emby webhook 重复处理
- 试运行模式：首次配置时只记日志不删除
- 白名单：只有配置的 Emby 路径前缀才被处理
- 回收站：STRM 文件和目录都走 7 天回收站 > ⚠️ v0.8.2 起已移除，改为直接物理删除，详见 [v0.8.2 更新日志](#v082)
- 删除历史持久化：`data/syncDelHistory.json`，最多保留 200 条

## v1.1.6 · 2026-08-29 · [对比](https://github.com/wabisabi926/faststrm/compare/v1.1.5...v1.1.6)

日常使用回归版本：Emby 通知完整、rename 干净、STRM 路由更稳、账号异常不再卡住。

### 🐛 修复

* **Emby 入库通知评分/主演/海报缺失** — 入库后多等一会儿让 Emby 刮削完再发通知（之前被父进程超时掐断了），同时主动请求完整元数据
* **rename/move 后旧目录残留** — 根文件夹路径没写入数据库、级联删除只删文件不删文件夹表，两处补齐
* **rename/move 信任了过期缓存** — 这类事件到达时数据库存的还是旧路径，现在跳过缓存强制走 API 刷新
* **创建 STRM 时数据库写入时机不对** — "已存在则跳过"模式下不生成 STRM 导致数据库也没记录，后续 move/rename 反查不到旧路径
* **.iso 电影重命名时关联资源丢失** — 去掉了 .iso 特殊处理，和其他文件一样只去掉最后一个扩展名，重命名 .nfo/.jpg/.srt 等不再漏掉
* **STRM 路由缓存串号** — 不同浏览器/设备的 User-Agent 可能拿到不同的 115 CDN 地址，现在缓存 key 带上 UA，避免换个设备就打不开

### ✨ 优化

* **账号异常不再卡住 STRM 生成** — 之前连续几次轮询失败后账号会退避冷却（从 2 分钟到 30 分钟），冷却期内该账号所有 STRM 都不生成。现在退避机制禁用，保持配置的轮询间隔
* **监控状态页信息补全** — Web 面板账号状态新增游标位置（FromID/FromTime）、连续错误数、退避状态等字段，方便排查
* **设置页监控配置读写修正**

### ✨ 其他

* 新增单元测试覆盖退避禁用、cookie 失效通知去重
* 移除重复的 wiki-sync workflow，保留带 Release 自动同步的那一个

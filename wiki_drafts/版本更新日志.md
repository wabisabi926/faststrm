## v1.3.1 · 2026-09-05 · [对比](https://github.com/wabisabi926/faststrm/compare/v1.3.0...v1.3.1)

入库通知更快、播放停止通知更简洁、设置保存更安全的一版。

### 亮点速览

- 入库通知速度大幅提升：刮削等待从最慢 43s 降到 25s，海报卡住不再拖 5 分钟
- 播放停止通知移除冗余的「观看时长」，播放进度已有时间不再重复
- Emby 设置保存时不再把脱敏 API Key 写回配置，避免真实 Key 被覆盖
- 新增 `--no-tray` 启动参数，无桌面环境也能跑

### ✨ 新增

- 新增 `--no-tray` 启动参数，跳过系统托盘初始化，方便在远程服务器、Docker 等无桌面环境下运行和调试

### ⚡ 优化

- 入库通知详情重试退避改为前密后疏（0.5/1/1.5/2/3/4/5/8s，总等待 43s→25s），刮削几秒完成即可几秒后发通知
- 海报下载超时从 300s 压缩到 8s，失败快速降级纯文本，不再因一张图片卡住整条通知
- Episode 防抖窗口从 15s 缩短到 8s，批量入库时通知更快发出
- 播放停止通知移除「观看时长」字段，播放进度已含时间（如 40:24 / 43:35）不再重复显示

### 🐛 修复

- 修复 Emby 设置页保存时脱敏 API Key（含星号占位符）被写回 settings.json 的问题，真实 Key 不再被覆盖
- 修复 monitor 刷库时 Series 类型入库事件被丢弃的问题，整剧入库现在也能正常发通知

## v1.2.3 · 2026-09-01 · [对比](https://github.com/wabisabi926/faststrm/compare/v1.2.2...v1.2.3)

统一 STRM 端点、废弃 enable302 开关的架构重构版本，同时修复远程目录浏览和弹窗闪退等一批生产 Bug。

### 🚨 破坏性变更

* `enable302` 配置字段已彻底删除（settings.json / 任务级 / 监控配置），所有 STRM 统一生成 `/api/strm?account=X&pickcode=Y`；旧 STRM 仍兼容（`/api/fs/get` 内部自动转发），建议用 `scripts/rebuild_strm.ps1` / `rebuild_strm.sh` 重建

### ✨ 新增

* 新增 STRM 重建脚本（PowerShell + bash 双版本），一键扫描替换旧 STRM 中的 `/api/fs/get` → `/api/strm`
* 新增 fs 转发一致性单元测试，验证两个端点响应 100% 相同
* 新增监控模块 STRM URL 生成测试，覆盖 prefix 变体 / URL 编码 / pickcode 兜底 5 组用例

### ⚡ 优化

* `/api/fs/get` 和 `/api/strm` 两个端点**逻辑合并**，智能路由（扩展名强制 proxy / UA 匹配 / 并发限流 / 302 预检）统一生效
* **ISO / BDMV / M2TS 原盘**自动走 proxy 模式（支持 Range seek），mkv / mp4 默认走 redirect（零服务器中转）
* 前端删除 enable302 UI 开关及相关类型定义，STRM 路由策略对所有 STRM 始终生效
* golangci-lint 全部通过（errcheck / gosec / unused / goimports 零告警）

### 🐛 修复

* 修复 URL **双重编码**：`http.Redirect` 对已编码的 STRM URL 二次编码导致 `?` 变 `%3F`、`&` 变 `%26`，现改为直接设置 Location 头 + 302 状态码
* 修复 embyproxy mustParseURL **panic 导致服务崩溃**：Emby URL 格式错误时优雅降级，不再硬崩整个服务
* 修复账户状态**假正常**：之前只检查 Cookie 字符串格式，过期也显示「正常」；现新增 `PingCookie` **真实调用 115 API** 验证 Cookie 有效性
* 修复远程目录**二三级错乱**：115 CID/FID 是 19 位整数，超过 JavaScript `Number.MAX_SAFE_INTEGER` 精度被截断，请求的 CID 变了 → 返回根目录内容。修复：后端 CID/FID 改为**字符串输出**，前端类型同步改为 string
* 修复远程目录**只能看一级**：后端无条件输出 `cid: 0`，前端把 0 当有效值请求根目录。修复：仅 `cid > 0` 时才输出；前端无有效 cid 时退用路径请求
* 修复定时任务窗口**闪退**：`nowTs` 每秒变化触发 `useMemo` 重建 columns → 表格重渲染 → Dialog 状态丢失。修复：用 `useRef` 包装时间戳，从依赖中移除

## v1.2.2 · 2026-08-31 · [对比](https://github.com/wabisabi926/faststrm/compare/v1.2.1...v1.2.2)

### 🐛 修复

* 修复 Emby for Kodi Gen 播放 ISO .strm 报「没有兼容的流」：URL `file_name` 和 115 `meta.FileName` 都为空时扩展名白名单短路，302 直跳 CDN 导致 Kodi Lavf HEAD probe 403/无头。`pickOneFileName` 升级 3 档兜底（URL 参数 > 115 meta > CDN 路径 basename PathUnescape），fs/strm 两个 DecideRoute 统一复用。`pickonefilename_test.go` 新增 9 例全覆盖。

* 修复 `/api/fs/get` 漏注册 MethodHead 路由：Lavf ISO probe 第一步严格发 HEAD，原厂只挂了 GET 返回 405，直接拍死整条 probe 链路。补注册 MethodHead 路由 + fs/strm 两处 handler 加 HEAD 短路径（不真转发 CDN HEAD，避免 signed URL 403）。

* 修复 HEAD 响应缺 Content-Length：115 download API 在部分账号/文件下 `meta.FileSize=0`（CDN Range 响应里 `/totalSize` 100% 正确，与 meta 字段解耦）。新增 `totalSizeFromCdn()` 极轻量 `Range: bytes=0-0` GET fallback，从 `/<totalSize>` 解析真实大小写回，成本 <30ms，失败安全回退。

* 修复 HEAD / GET `Access-Control-Expose-Headers` 不一致：跨域发 HEAD probe 时 CORS 吞掉 Content-Length / Accept-Ranges。统一对齐 GET 暴露头列表。

## v1.0.5

**2026-08-24** · [与 v1.0.3 对比](https://github.com/wabisabi926/faststrm/compare/v1.0.3...v1.0.5)

### 🎯 核心可靠性增强：熔断保护 + 事件处理修复 + 关联文件安全

### 🐛 关键 Bug 修复

- **修复 type=17 (new_folder) 事件错误生成 STRM**：空文件夹事件被误判为创建事件而生成 STRM 文件，现添加 isNewFolderOnly 判断，type=17 仅写入数据库记录文件夹路径，不生成 STRM
- **修复软删除/.bak 备份残留**：彻底移除 EnableHardDelete 配置项，所有删除操作直接调用 os.Remove/RemoveAll，不再生成 .deleted.bak 备份文件
- **修复移动/重命名事件目标路径已存在时被跳过**：local_move 模式下目标路径已存在时直接跳过，现改为 fallback 到 recreate 模式，解决 115 先创建后移动的时序问题
- **修复关联文件删除可能误删非关联文件**：deleteRelatedFiles 添加扩展名验证，防止 "movie" 匹配到 "movie_trailer.mp4"

### 新增

- **删除事件熔断保护**：单次轮询中删除事件 > 100 条或占比 > 50% 时，自动跳过所有删除操作，防止 API 异常导致大规模误删
- **仅错误通知模式**：LifeMonitor 设置页新增开关，开启后正常操作不推送 TG 通知，仅异常时推送

### 优化

- Emby 入库通知链路完善：添加 GetItemDetailWithRetry 重试方法应对 Emby 异步写入延迟
- Emby webhook URL 复制支持 HTTP 环境降级处理
- 前后端硬删除配置统一

## v1.0.3

**2026-08-24** · [与 v1.0.2 对比](https://github.com/wabisabi926/faststrm/compare/v1.0.2...v1.0.3)

### 🐛 关键 Bug 修复

- **修复 115 生活事件 API 响应 count 字段为字符串导致 JSON 解析失败**：proapi 端点返回的 count 字段是字符串而非数字，next_page 也可能返回非 bool 类型，导致 Go 反序列化报错，事件拉取直接失败。现将 Count 和 NextPage 改为 any 类型，并新增 parseNextPage 辅助函数灵活处理 bool/int/string。

## v1.0.2

**2026-08-24** · [与 v1.0.1 对比](https://github.com/wabisabi926/faststrm/compare/v1.0.1...v1.0.2)

### 🐛 关键 Bug 修复

- **修复 115 生活监控生成 STRM 完全不生效**：PullEvents 默认调用 `webapi.115.com/behavior/detail`（Web API），该端点返回的事件 `pick_code` 字段经常缺失，导致单文件创建事件被 `invalid_pickcode` 拦截器全部跳过，永不进入 handleCreateEvent 生成 STRM。对照参考项目 p115strmhelper 与 p115client 源码后，改为默认走 `proapi.115.com/ios/behavior/detail`（字段完整含 pick_code），失败时回退 webapi（对齐参考项目 fallback 策略）。同时修复了原 proapi 切换时 URL 缺 `/ios` 前缀导致 404 的 bug；并修复了 `useAlternateHost` 状态泄漏导致一次切换后永久走 webapi 的问题。
- **修复 STRM 删除时默认生成 `.deleted.bak` 备份**：原 `EnableHardDelete` 默认 false（软删除），导致 115 删除文件后本地 STRM 被改名为 `.deleted.bak` 占用磁盘空间。现默认改为 true（硬删除直接 os.Remove），并在 LifeMonitor 设置页新增「硬删除（不生成 .deleted.bak 备份）」复选框；旧配置迁移：检测到无 `enableHardDelete` 字段时自动设为 true，不覆盖用户后续显式关闭的选择。

### 新增

- Emby webhook 入口新增诊断日志 `[emby/webhook] 收到 webhook: Event=... Item=... Type=...`，方便用户排查"入库通知不生效"时确认 webhook 是否真的收到（若日志没出现说明 Emby 端事件类型未勾选"新建项"）
- LifeMonitor 设置页新增「硬删除（不生成 .deleted.bak 备份）」开关

### 优化

- `FsFilesMediaAncestors` 独立固定 webapi 调用，不再被 life API 的 proapi/ios 切换影响，避免回归

## v1.0.1

**2026-08-24** · [与 v1.0.0 对比](https://github.com/wabisabi926/faststrm/compare/v1.0.0...v1.0.1)

### 🎯 核心体验升级：任务管理 UX + Telegram/Emby 通知质量

大库首次生成时「目录扫描看起来卡死（0% 静止不动）」的感知焦虑彻底解决：任务面板现支持 9 阶段徽章、实时已用计时器、扫描阶段骨架动画进度条、每 3 秒「已扫描 N 目录 M 文件」活度心跳。同时对齐参考项目 qmediasync 的 TG / Emby 通知模板，补齐图片、观看时长、排版对齐等问题。

### 🐛 关键 Bug 修复

- **Emby 通知全链路失效**：全局 `client==nil` 判断阻塞未初始化调用方，通知分发器隔离异常
- **STRM 任务 Telegram 通知不触发**：executor 缺少 TaskNotifier 接入，dispatcher 调用链断裂
- **TG Bot 按钮点击无响应**：Webhook/NotifyPollingPOST 使用空的 deps.CommandHandler，改为懒加载 cmdHandler 注入
- **开机自动轮询不启动**：server.Run 启动时漏掉 `settings.Telegram.AutoPolling` 判断
- **TG 通知排版错位**：中文/Emoji 宽度不等导致排版错乱，全量替换空格为 `&nbsp;` 并统一粗体包裹
- **生活监控通知重复发送**：event_handler 中同一事件双调用 NotifyWithPhoto，60s batcher 重复入队
- **Emby 通知缺少封面图**：ImageTags 大小写未匹配 + TG 服务器无法访问内网 Emby URL，现下载为临时文件再上传
- **Emby 播放暂停/停止缺"⌛ 观看时长"**：对齐 qmediasync 补齐
- **Emby 演员图标风格不一致**：统一由 👤 改为 👥

### 新增

- 新增 RuntimeState.Stage / StageDetail：9 阶段常量（starting / scanning / incremental / cleanup / writing_db / generating / finalizing / completed / failed）
- 新增 SSE ProgressPayload.Stage / StageDetail 字段
- 新增 `listAllFilesRecursive` 活度心跳：每 3 秒广播「已扫描 N 个目录, M 个文件 (命中 K 个媒体)」
- 新增任务面板阶段徽章：🔍 扫描目录 / 📊 增量比对 / 🧹 清理文件 / 💾 写数据库 / ⚡ 生成 STRM / 🔧 收尾处理
- 新增任务面板「已用时间」计时器（每秒刷新）
- 新增 scanning 阶段骨架进度条：条纹 shimmer + 青色扫光块循环动画

### 优化

- Emby 通知模板对齐 qmediasync：清晰度 / 设备信息 / 播放格式 / 封面图尺寸升级到 720p
- `BuildImageURLIfAvailable` 改为大小写不敏感查找 ImageTags，兼容不同 Emby 版本
- 图片发送链路统一：「下载临时文件 → SendPhotoFromFile」
- executor 所有 9 阶段均设置 Stage 并广播，失败路径同步 StageDetail=err
- Emby 入库 / 播放 / 暂停 / 停止 四场景通知排版对齐 qmediasync 风格

## v1.0.0

**2026-08-22** · [与 v0.9.9 对比](https://github.com/wabisabi926/faststrm/compare/v0.9.9...v1.0.0)

### 🎯 核心重构：生活事件监控完全对齐参考项目

实现四象限决策矩阵，事件类型路由，并移除所有 fallback 逻辑——rename/move 失败直接返回错误，与参考项目 `shutil_move` 抛异常行为一致。

### 🐛 关键 Bug 修复

- **STRM 路径映射丢失子目录**：修复 4 处 `filepath.Dir(mapping.localPath)` 误用，改为直接使用 `mapping.localPath` 作为 STRM 父目录
- **DB 提前覆盖旧路径**：删除 `handleMoveRenameQuadrant` 中提前写 DB 的调用，handler 内部反查旧路径后才同步 DB
- **recreate 模式不生成新 STRM**：recreate 模式强制创建新 STRM，不再被 `moveMediaCreateNewStrm` 配置挡住
- **OTHER_TO_MEDIA 象限旧 STRM 未清理**：新增 `cleanupOldStrmForOtherToMedia` 函数，创建新 STRM 前按 file_id 反查并删除旧 STRM

### 新增

- 新增四象限决策矩阵，对齐参考项目 p115strmhelper
- 新增事件类型路由（type∈{1,2,14,18,23}→create, type∈{5,6}→move, type∈{20,24}→rename, type==22→remove）
- 新增 phase1.go（事件预处理 + 路径映射决策）
- 新增 cleanup_interaction.go（STRM 清理交互确认 API）
- 新增 strm_history.go + strm_history_repo.go（操作级历史记录）
- 新增 notification_batcher.go（60 秒通知合并器）
- 新增 pkg/concurrency（AC 自动机 + workerpool）
- 新增 pkg/strmutil/safedelete.go（安全删除工具）

### 优化

- 115 API：Use-Agent 轮换池 + 429 自动切换 + 域名修正（proapi.115.com）
- 115 API：分级超时（普通 30s / 慢操作 300s）+ 账号级速率限制
- 302 路由：405 fallback + 二次 pickcode + 并发锁
- STRM 清理：双阈值（max=10 / stable=5）+ UI 二次确认
- Emby 刷库：防抖 10 秒
- SQLite：WAL 模式 + busy_timeout=5000

### 配置变更

- `enableHardDelete` 默认改为 true（物理删除，不留 .deleted.bak）
- `moveMediaCreateNewStrm` 默认改为 true（recreate 模式强制生新）
- `renameAutoRelatedFiles` / `moveLocalMoveRelatedFiles` / `moveOutRemoveLocalStrm` 默认 true

## v0.9.6

**2026-08-21** · [与 v0.9.5 对比](https://github.com/wabisabi926/faststrm/compare/v0.9.5...v0.9.6)

### 🎯 核心：飞牛 fNOS 路径权限、任务日志 & 监控状态修复

fNOS 分支路径权限与显示逻辑对齐参考项目 qmediasync，修复应用目录选择、远程→本地路径回填、任务日志查看、监控状态等关键场景。

### 🐛 关键 Bug 修复

- **fNOS 路径返回白名单过宽**：之前会枚举系统挂载点（`..`、`.` 等）+ 硬编码 NAS 卷根，导致用户看到 20+ 无关路径；`directory.go` 仅返回 `+`，和 qmediasync 行为一致
- **未授权缺少友好提示**：fNOS 环境下无授权路径时直接报错，用户不知道怎么开；现已返回提示文案，引导在飞牛应用设置勾选「存储卷」权限
- **远程路径后本地路径被错误自动填写**：`DirectoryTreeDialog.tsx` 选择远程路径后本地路径被错误填成同名（多为无效路径），导致任务在应用工作目录下创建而非用户期望的媒体根；已删除错误自动填写弹窗
- **任务日志查看失败**：API 路径与前端接口契约不匹配，修复 `/api/tasks/:id/logs` 返回格式
- **生活事件监控状态显示不准确**：前端 status 枚举与后端实际值不匹配；统一为 `running / paused / error`
- **生活事件监控 API 路径错误**：监控轮询与状态接口路径不一致，修正为正确的 `/api/life-monitor` 前缀

### 新增

- 新增 fNOS 安装向导自定义端口配置（默认 8090）
- 新增 `LocalDirectoryTreeDialog.tsx` 空列表友好提示：保存后端提示信息 + 引导用户用输入框粘贴路径跳转

### 优化

- 精简应用图标，移除 fNOS 包中冗余多尺寸 png（仅保留 ICON.PNG / ICON_256.PNG）
- 统一 fNOS 默认管理员密码为 `admin`，与 qmediasync 保持一致

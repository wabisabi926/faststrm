# 生活事件监控

生活事件监控是 Fast Strm 的实时同步能力：每 30 秒轮询 115 网盘生活事件，自动同步本地 STRM，无需等待定时全量扫描。

---

## 启用监控

1. 进入「设置」→「生活监控」
2. 勾选「启用监控」
3. 选择要监控的 115 账号
4. 配置路径映射
5. 保存后会自动开始首次拉取

### 服务重启后自动启动

从 v0.8.2 起，监控支持「懒加载自动启动」：

- 服务重启后，**首次有用户访问监控相关页面或接口时**，系统会自动检查：
  1. 监控配置中「启用监控」是否打开
  2. 监控账号列表是否非空
  3. 每个账号的 Cookie / 凭据是否存在（115：cookie 非空；openlist：url/account/password 齐全）
- 三项条件同时满足，会自动调用 `startMonitor()` 拉起监控，**无需再手动点击「全部启动」**
- 真正的 Cookie 有效性由首次轮询（`oncePoll`）自动检测，若失效会把该账号状态置为 `error`，不会阻塞或死循环
- 每进程仅执行一次（通过 `globalThis.__lifeMonitorsAutoStarted` 保护），HMR 热重载后仍然稳定

## 路径映射

监控通过路径映射确定「网盘路径变动 → 哪个本地 STRM 目录受影响」：

```json
[
  {
    "account": "我的115",
    "cloudPath": "/电影",
    "localPath": "/app/data/strm/电影"
  },
  {
    "account": "我的115",
    "cloudPath": "/电视剧",
    "localPath": "/app/data/strm/电视剧"
  }
]
```

- 只有映射的 `cloudPath` 下的变动才会被处理
- 网盘根目录变动（不在映射内）会被忽略

## 四类事件处理

### 创建事件（create）

**场景**：115 网盘新增文件/文件夹（上传、转存、离线下载完成）

**处理流程**：
1. 解析文件路径（通过 cid 反查）
2. 在路径映射范围内 → 生成 STRM
3. 文件夹事件 → 递归生成所有子文件 STRM
4. 写入 filePathDb
5. 触发 Emby 刷新（防抖 10 秒）

### 删除事件（remove）

**场景**：115 网盘删除文件/文件夹

**处理流程**：
1. **熔断检查**：单次轮询删除数 >100 或占比 >50% → 跳过并告警
2. 通过 fileId 在 DB 反查本地 STRM 路径
3. 直接物理删除 STRM 文件（`fs.unlinkSync`）
4. 删除 DB 记录
5. 清理空目录（保护映射根目录）
6. 触发 Emby 刷新

> ⚠️ **熔断保护**：防止 115 API 返回异常导致大规模误删。STRM 删除为直接物理删除，无回收站；误触发后可在 115 网盘恢复文件后重新全量扫描生成。

### 重命名事件（rename）

**场景**：115 网盘重命名文件/文件夹

**处理流程**：
1. 通过 fileId 反查旧路径
2. 删除旧 STRM
3. 用新名称重新生成 STRM
4. 更新 DB

### 移动事件（move）

**场景**：115 网盘移动文件/文件夹

**处理流程**：
1. 解析新旧路径
2. 判断移动类型：
   - **映射内移动** → 删除旧 STRM，在新位置生成
   - **移入映射** → 在新位置生成 STRM
   - **移出映射** → 删除旧 STRM + 空目录
3. 更新 DB

## 首次拉取模式

`firstPullMode` 控制首次启用监控时如何处理历史事件：

| 模式 | 行为 | 适用场景 |
|------|------|----------|
| `latest` | 只拉取最新一批事件 | 默认，避免重复生成 |
| `all` | 拉取所有历史事件 | 需要补齐遗漏 |
| `last` | 从上次断点继续 | 重启后恢复 |

---

## 断点恢复

`lifeMonitorState.json` 记录每个账号的最后处理时间戳：
- 容器重启后从断点继续，不会遗漏事件
- 如果断点超过 7 天（115 历史保留期），自动切换到 `latest` 模式

---

## 与全量扫描的互斥

全量扫描任务执行时会自动暂停监控，避免 API 和 DB 竞争：

1. 全量扫描开始 → `suspendMonitorForFullScan(account)`
2. 全量扫描结束/异常 → `clearMonitorSuspend(account)`（finally 保证）
3. 监控超时恢复：10 分钟（`FULLSCAN_TIMEOUT_MS`）

---

## API 降级

115 生活事件 API 有两个端点：
- **iOS API**（`/ios/...`）：返回结构更完整，但偶发 405
- **Web API**（`/web/...`）：稳定，但某些字段缺失

监控自动降级：iOS 405 → 切 Web API，用户无感。

---

## 移动/重命名模式

`moveMediaMode` 控制移动事件的处理方式：

| 模式 | 行为 |
|------|------|
| `recreate`（默认） | 删旧 STRM + 在新位置重新生成 |
| `local_move` | 本地移动 STRM 文件（更快，但路径映射必须精确） |

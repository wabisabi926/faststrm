# Telegram 通知

Fast Strm 支持通过 Telegram Bot 推送通知，包括任务状态、Emby 事件、删除同步等。

---

## Bot 配置

### 1. 创建 Bot

1. Telegram 搜索 `@BotFather`
2. 发送 `/newbot`
3. 按提示设置名称和用户名
4. 获得 **Bot Token**（如 `123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11`）

### 2. 获取 Chat ID

1. 先给你的 Bot 发一条消息
2. 浏览器访问：`https://api.telegram.org/bot<TOKEN>/getUpdates`
3. 在返回的 JSON 中找到 `chat.id`

> 💡 群组通知：把 Bot 加入群组，Chat ID 通常为负数（如 `-1001234567890`）。

### 3. faststrm 配置

进入「通知」→「TG 通知」页面：

| 字段 | 说明 |
|------|------|
| Bot Token | 从 BotFather 获取 |
| Chat ID | 接收通知的会话 ID |
| 启用通知 | 总开关 |
| 启动时自动轮询 | 服务启动时自动启动轮询（默认开启） |
| 允许的用户 | 允许通过 Bot 交互的用户 ID（可选） |

### 4. autoPolling 自启动说明（v0.8.6 新增）

当「启动时自动轮询」开启后，服务启动时会自动检查以下条件并启动轮询：

1. ✅ Bot Token 已配置
2. ✅ 启用通知已开启
3. ✅ 未配置 Webhook URL
4. ✅ autoPolling 未被关闭

**运行时自愈**：轮询运行中如果定时器失效（进程崩溃/HMR 导致），系统会自动检测并重启轮询，无需人工干预。

**手动控制**：即使启用了 autoPolling，仍可通过页面上的「启动」/「停止」按钮手动控制轮询。

### BotFather 权限命令

配置 Bot 时，以下命令需在 BotFather 中执行以授予对应权限：

| 命令 | 权限说明 |
|------|----------|
| `/setprivacy` → `Disable` | 允许 Bot 读取群组消息（群聊交互必需） |
| `/setjoingroups` → `Enable` | 允许 Bot 加入群组 |

> 💡 页面上会直接显示需要执行的 BotFather 命令，方便对照操作。

## 通知类型

### 任务通知

| 事件 | 消息内容 |
|------|----------|
| 任务开始 | 任务名 + 账号 + 开始时间 |
| 任务完成 | 任务名 + 生成数 + 删除数 + 耗时 |
| 任务失败 | 任务名 + 错误信息 |

### Emby 通知

| 事件 | 消息内容 |
|------|----------|
| 媒体入库 | 标题 + 类型 + 路径 |
| 媒体删除 | 标题 + 类型 |
| 播放开始 | 标题 + 客户端 + 用户 |
| 播放结束 | 标题 + 播放进度 + 停止位置 |

### 删除同步通知

| 事件 | 消息内容 |
|------|----------|
| Emby 删除同步 | 标题 + 类型 + 删除文件数 |
| 试运行模式 | 带 `[试运行]` 标记 |

### 账户状态通知（v0.8.2 新增）

在「TG 通知」页面 → 「账户状态通知」卡片配置：

| 字段 | 说明 |
|------|------|
| 启用账户状态通知 | 总开关 |
| 异常通知 | 账号 Cookie 失效等异常时推送告警 |
| 恢复通知 | 账号恢复正常时推送通知 |

**闭环流程**：账号异常 → TG 推送告警 → 用户在「账号管理」点击「更新 Cookie」扫码刷新 → 后端异步重检状态 → 恢复正常后推送恢复通知

> 对应配置：`settings.json → telegram.accountAlerts`，详见 [配置参考](配置说明#accountalerts-格式v082-新增)。

## 剧集缓冲合并

Emby 入库电视剧时，单集会逐个推送事件。faststrm 会缓冲合并：

- **窗口**：10 秒
- **合并条件**：同一剧集（SeriesId）的多集入库
- **合并后消息**：`《剧名》新增 S01E01-E10 共 10 集`

> 避免一季 24 集入库时刷屏 24 条消息。

## Webhook vs 轮询

| 方式 | 说明 | 适用场景 |
|------|------|----------|
| **轮询（推荐）** | faststrm 主动调 `sendMessage` API 推送通知 | 本地 NAS / 内网部署，无需公网 |
| Webhook | TG 服务器回调 faststrm，需公网可达 | 需要双向交互（Bot 指令回复） |

> 💡 **推荐轮询模式**：大多数本地 NAS / 内网部署场景无需公网 IP，轮询模式开箱即用。Webhook 模式需要 faststrm 可被外网访问，适用于需要用户通过 Bot 指令交互的高级场景。
>
> 轮询模式下，Webhook 信息卡片会自动隐藏，界面更简洁。

## 交互指令

配置 `allowedUsers` 后，被允许的用户可以与 Bot 交互：

| 指令 | 功能 |
|------|------|
| `/status` | 查看任务状态 |
| `/tasks` | 列出所有任务 |
| `/run <任务名>` | 执行指定任务 |

> 交互功能依赖 Webhook 模式。

## 故障排查

| 问题 | 原因 | 解决 |
|------|------|------|
| 收不到通知 | Chat ID 错误 | 重新获取 getUpdates |
| 401 Unauthorized | Token 错误 | 重新从 BotFather 获取 |
| 403 Forbidden | Bot 未加入群组 | 把 Bot 加入目标群组 |
| 429 Too Many Requests | 发送过频 | 剧集缓冲合并已处理 |

### 手动验证 Token

```bash
curl https://api.telegram.org/bot<TOKEN>/getMe
```
